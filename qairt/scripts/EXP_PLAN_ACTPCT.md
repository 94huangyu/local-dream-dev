# EXP_PLAN_ACTPCT —— 激活改用 percentile 校准（量程收紧 3.6 倍），能否再推进一步？

定稿时间：2026-08-16 11:20（**执行前定稿，判据不得事后修改**）
台账归属：**#53**（#9 的重开）
前置：`EXP_PLAN_PERROW`（per-row 有效，part1b cos_bulk 0.6033→0.7986）
      `EXP_PLAN_PERROW3` 2/3 配置（46.73→43.56→41.37，**改善传导了但远远不够**）

## 0. 假设与证据

**H-act**：HTP 误差随**量化步长**变化（#52 已在权重侧双向验证）。
权重侧的步长已经细化 3.9 倍并拿到收益；**激活侧从未动过**，
其量程由 min-max 校准决定、被离群值撑得极宽。收紧激活量程应带来同类收益。

**支持证据（全部①实测）**：
1. **#52**：权重 scale ×1.073（粗）⇒ 设备 cos_bulk −0.0526；×0.26（细）⇒ +0.2479。
   **步长是驱动量**，且 CPU 侧对同一改动几乎无感（放大 37.6 倍）。
2. **15.12**：`unified` 的 encoding 是 `[-145.277, 6265.993]`、scale 0.0978，
   而张量**主体 std 仅 15.11** ⇒ **16 bit 的量程里主体只用到约 10 bit**
   （±3σ 仅占 1.414% 的量化级）。`percentile`(p99.99) 实测可收紧 scale **3.6 倍**。
3. **`EXP_PLAN_CH85_CAUSAL`**：离群点占**输入误差能量 64.28%**，
   却只造成 **23%** 的下游损害；主体占 36% 能量却造成 **99%**。
   ⇒ **钳掉离群、换主体分辨率细 3.6 倍，是划算的交易。**
4. **2/3 在环实测**：权重侧表示误差已降到 0.27 倍，成图仍坏
   ⇒ 剩余误差大头**不在权重表示**。

**#9 当初为什么被关掉，以及为什么那个理由不成立**：
#9 的关闭依据是"percentile 会钳掉 48~99.97% 的能量；MSE 最优解就是 min-max；
16-bit 表示误差仅 0.32%"——**全部是表示误差/MSE 论证**。
而 #52 与本轮 2/3 实测共同证明：**表示误差不是 HTP 误差的预测量**。
⇒ 该关闭论证在 HTP 上不成立。**保留原结论不删，标注推翻理由**（约束 2）。

## 1. 单变量设计

比较对象**不是基线，而是当前最优的 per-row 配置**——这样才是单变量：

```
qairt-quantizer --input_dlc  transformer_part1b_fp32.dlc          <- 与 per-row 那次同一份
                --output_dlc part1b_perrow_pct_quantized.dlc
                --input_list <同一份 input_list_raw.txt>
                --weights_bitwidth 8 --act_bitwidth 16 --bias_bitwidth 32
                --use_per_channel_quantization --use_per_row_quantization   <- 保持
                --param_quantizer_calibration min-max                       <- 保持
                --act_quantizer_calibration percentile                      <- 唯一改动
                --percentile_calibration_value 99.99                        <- 唯一新增
```

⇒ 与 per-row 那一版**只差激活校准方式**。

## 2. 先决门

**G1（改动生效）**：新 DLC 里 `unified` 的激活 scale 必须**明显小于** per-row 版。
判据：`scale_new / scale_perrow < 0.5`。
若基本不变 ⇒ percentile 对本模型空转（同 #44 的结局），**立即停止**，不建图。

**G2（只动了激活）**：59 个 FC 权重仍为 per-axis `sFxp_8`、`axis: 0`，
数量与 per-row 版一致（**66 个 axis-quant 张量**）。

**G3（建得出 `.bin`）**：`qnn-context-binary-generator` EXIT=0 且无 `validateOpConfig` 报错。
⚠️ **part1b 的 context 是 1.47 GB，不触及 #55 那个 >2.9 GB 的可疑上限。**

**G4（设备有效性）**：宿主/设备 md5 一致；输出 63,406,080 字节；两次运行 md5 相同。

## 3. 判据（事后不得修改）

真值 = `vs_fp32/unified_fp32.raw`；口径 = 主体；工具 = `metrics_unified.py`。
**比较对象 = per-row 版的 `cos_bulk = 0.7986`**（不是基线的 0.6033）。
无效变更本底 ±0.001（O=3 实测标定）。

| 结果 | 判定 |
|---|---|
| `Δ ≥ +0.05` | **H-act 成立** ⇒ percentile 是第二个有效杠杆，推进三段 |
| `+0.005 ≤ Δ < +0.05` | 微弱有效，**不足以支撑三段重量化的成本**，如实记录数值 |
| `\|Δ\| < 0.005` | **H-act 否定**（本底 5 倍内）⇒ 激活量程不是剩余误差的驱动量 |
| `Δ ≤ −0.005` | **变差** ⇒ 否定，且说明钳掉离群点确有代价，记录该反直觉事实 |

**次判据（机制）**：`slope_bulk`（per-row 版为 1.0435）与主体 std（per-row 0.8146，
FP32 真值 0.6235）。若 std 明显向 0.6235 收敛，说明弥散噪声被压下去了。

**对照判据**：⛔ **无法执行**——SNPE CPU 参考不支持 axis-quant 的 FullyConnected
（`error_code=202`，见 #47）。**不计为通过，如实标注缺失。**

## 4. 成功 / 失败判断

- **成功**：拿到 `cos_pct` 并按判据给出明确分支。
- **失败·执行方法错误**：G1 空转 / 建图失败 / OOM ⇒ 修方法重跑，判据不变。
- **失败·方向错误**：门全过但 `|Δ| < 0.005` ⇒ H-act 被否定，
  **主线转向"非量化配置"类解释**（#30 单 MatMul 探针的结果将决定是 #32 SDK 版本还是选择性 FP16）。

# 执行结果（2026-08-16，判据未事后修改）

## 6. G1 / G2（通过）

| 门 | 结果 |
|---|---|
| **G1 激活量程确实收紧** | ✅ **且强于预期**。`unified` 的激活 encoding：<br>· per-row（min-max）：`[-145.244, 6255.937]`，scale **0.097676**<br>· **+percentile p99.99**：`[-25.314, 815.503]`，scale **0.012830**<br>⇒ scale 比值 **0.1314**（判据要求 < 0.5）；**量化步长细了 7.6 倍**（15.12 的估算是 3.6 倍，实测更好） |
| **G2 只动了激活** | ✅ axis-quant 张量 **66 个**，与 per-row 版一致 ⇒ 权重侧未被牵连 |

量化耗时约 62 分钟（min-max 版 54 分钟；percentile 需要建直方图，略慢）。
产物 1399970400 字节（per-row 版 1399970464，差 64 字节 = 内嵌命令行长度差）。

> ⚠️ 值得记录的一点：p99.99 把 `unified` 的上界从 **6255.9 砍到 815.5**。
> 被钳掉的是最大的 0.01% 的值，而张量主体 std 仅 15.11 ⇒
> 这正是 15.12 说的"16 bit 量程里主体只用到约 10 bit"的直接修正。

## 7. 主结果：❌ **H-act 被否定，且是大幅倒退**

真值 = `vs_fp32/unified_fp32.raw`，主体口径（能量集中度 99.83%）。

| 配置 | E_all | E_bulk | **cos_bulk** | slope |
|---|---|---|---|---|
| 基线 | 19.2406% | 114.798% | 0.6033 | 0.8622 |
| per-row（比较对象） | 7.8665% | 78.771% | **0.7986** | 1.0435 |
| **per-row + percentile p99.99** | **35.8023%** | 134.263% | **0.4793** | 0.7168 |

`Δ = 0.4793 − 0.7986 = −0.3193` ≤ −0.005 ⇒ **落入事前判据的「变差 ⇒ 否定」分支。**

## 8. 🔴 事后补做代价门，发现**这个实验根本不该跑**

用已有的 `unified_fp32.raw` 做 quantize-dequantize 模拟（10 秒）：

```
unified 真实量程 [-112.54, 6219.57]
被 p99.99 钳掉:  4142 个元素（0.0261%），**占 ||a||² 的 98.75%**

仅量化表示误差（不含任何 HTP 执行误差）:
  min-max encoding      全量  0.1884%   主体 4.5227%
  percentile encoding   全量 32.0212%   主体 0.5941%
```

**纯表示误差 32.02% > 当时的端到端误差 7.87%** ⇒ 不可能有收益。
实测 E_all 35.80% 与这个 32.02% 的地板几乎重合 ⇒ **本次失败几乎全部由"钳量程"本身造成，
与 HTP 无关，设备时间白花。**

⇒ 已固化为 **约束 4·补 G0-cost 门**：改 encoding 前必须先算纯表示误差，
   超过当前端到端误差就直接否决。

## 9. 机制修正（本实验唯一的正向产出）

**"细步长有收益"只在动态范围完整保留时成立：**
- per-row：每行用自己的量程，**范围不丢** ⇒ 主体余弦 +0.2479
- percentile：**砍掉量程**换分辨率，范围丢了 ⇒ 主体余弦 −0.3193

⇒ #52 的结论**范围收窄**：不能表述为"HTP 误差随量化步长单调变化"，
   必须表述为"**在动态范围保持不变的前提下**，HTP 误差随量化步长单调变化"。

## 10. 对 #9 的处理（约束 2：结论被推翻时保留原文并标注）

#9（激活 min-max 校准）当初被关闭，**结论是对的**（min-max 确实优于 percentile），
只是当时给的理由（"MSE 最优解就是 min-max"）与 HTP 的实际机制无关。
⇒ **#9 恢复为已关闭**，但关闭理由更新为：**实测 percentile 使设备主体余弦下降 0.3193**，
   而非原来的 MSE 论证。
