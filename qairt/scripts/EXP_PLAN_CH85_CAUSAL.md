# EXP_PLAN_CH85_CAUSAL —— part1b 的 19.47% 里，是"12 个极端点"还是"弥散本底"在毁图？

定稿时间：2026-08-15（执行前定稿，判据不得事后修改）
主线归属：A → C 的机制层

## 0. 触发这个实验的实测发现

`part1b` 输出 `unified` 的 HTP vs CPU 差异（相对 L2 **19.47%**）在结构上**极不均匀**：

```
p50=0.373(0.02σ)  p99.9=3.05(0.20σ)  p99.99=103.2(6.83σ)  max=2733(180.9σ)
```

最大的 8 个差异点**全部位于通道 85、caption 的 padding 槽位（token 4116~4127）**：

| token | ch | CPU 参考 | HTP | 比值 |
|---|---|---|---|---|
| 4127 | 85 | 6169.08 | 3436.04 | 0.557 |
| 4122 | 85 | 6178.04 | 3451.15 | 0.559 |
| 4117 | 85 | 6187.81 | 3461.68 | 0.559 |

HTP 稳定给出 CPU 值的 **约 55.8%**——**系统性**，不是噪声。
且 `unified` 的量化范围上界是 **6265.99**，这些值处在量程 **98.6%** 处。
按能量估算，这十几个点约占 part1b 全部 L2 误差能量的 **~81%**（②推论，本实验会精确复核）。

**但"占误差能量的大头"≠"是毁图的原因"**（差异≠根因，本项目已多次栽在这上面）。
下游 part2 的注意力会把 4128 个 token 混合，弥散本底也可能才是真正起作用的部分。

## 1. 预期结果（假设）

**H-outlier**：把 CPU 参考的 `unified` 里那批极端点换成 HTP 的值，
part2 的输出就会显著劣化 ⇒ 极端点是主要致害因素。

零假设：换掉极端点几乎不影响 part2 输出，而换掉弥散本底才影响
⇒ 致害的是弥散误差，极端点只是"看起来吓人"。

## 2. 实现路径（**全程走 CPU 参考，不引入 HTP 执行这个变量**）

关键设计：part2 **一律用 SNPE CPU 参考跑**（`scripts/snpe_runner.py`，约束 3）。
这样唯一的变量就是"喂进去的 `unified` 里哪些元素被换成了 HTP 值"。

设 `U_cpu` = CPU 参考的 part1b 输出，`U_htp` = 宿主 `.bin` 在 HTP 上的 part1b 输出。
定义掩码 `M` = |U_htp − U_cpu| 最大的前 K 个元素（K 取 16，覆盖那批 ch85 极端点）。

四次 part2 运行（全部 CPU 参考）：

| 变体 | 喂给 part2 的 unified | 测什么 |
|---|---|---|
| **基线** | `U_cpu` | 参照（= testB s0 的 latents） |
| **全 HTP** | `U_htp` | 上界：part1b 全部误差的下游影响 |
| **仅极端点** | `U_cpu`，但 M 处换成 `U_htp` | 极端点单独的贡献 |
| **仅本底** | `U_htp`，但 M 处换回 `U_cpu` | 弥散本底单独的贡献 |

其余输入（`adaln_input` / `unified_freqs` / `unified_mask`）四次全部相同，取 CPU 参考值。

## 3. 验收标准（判据，事后不得修改）

对每个变体，算其 part2 输出 `latents` 相对于**基线**的相对 L2，记为
`R_all`（全 HTP）、`R_out`（仅极端点）、`R_base`（仅本底）。

**判据 1（归因）**：
- `R_out / R_all > 0.7` 且 `R_base / R_all < 0.3` ⇒ **极端点是主因**，H-outlier 成立。
  下一步聚焦"HTP 为何把量程 98.6% 处的值算成 55.8%"。
- `R_base / R_all > 0.7` 且 `R_out / R_all < 0.3` ⇒ **弥散本底是主因**，H-outlier 被否定。
  下一步转向全局精度配置，**不要**再纠结 ch85。
- 两者都在 0.3~0.7 之间 ⇒ 两者都有实质贡献，按比例报告，不得只归因一边。

**判据 2（自洽性检查）**：`R_all` 必须与"直接用 HTP 的 unified 喂 CPU part2"一致（同一次运行）。
且 `R_out` 与 `R_base` 的平方和应大致接近 `R_all` 的平方（误差可加性），
若严重不成立说明 part2 对该扰动高度非线性，需在结论中注明。

**判据 3（能量占比复核）**：精确计算 M 处元素占 `||U_htp − U_cpu||²` 的比例，
验证第 0 节"~81%"这个②推论。若实际远低于 81%，说明该推论错误，需更正文档。

## 4. 成功 / 失败判断

- **成功**：拿到三个比值，按判据 1 给出明确归因。
- **失败·执行方法错误**：`snpe_runner.py` 抛契约错误 / part2 跑不动。修方法重跑，判据不变。
- **失败·方向错误**：四个变体输出**完全相同** ⇒ 说明 unified 的改动没生效
  （比如写错了索引），必须查清，不得解读为"扰动无影响"。

## 5. 预算与放弃条件

- 预算：4 次 CPU 参考 part2（每次数分钟）。
- 这是**机制层**实验，不影响已确立的根因结论（C 已坐实）。
  若两轮拿不到清晰归因，停止，回主线按"设备侧 prepare"那条线走。

# 执行结果（2026-08-15，判据未做任何修改）

四次 CPU 参考 part2 全部成功（`snpe_runner.py` 四项契约检查均通过）。

| 变体 | latents std | 相对基线的相对 L2 | 占 R_all |
|---|---|---|---|
| 基线 `U_cpu` | 1.6396 | — | — |
| 全 HTP `U_htp` | 1.7393 | **52.8711%** | 1.000 |
| 仅极端点（M 处换 HTP） | 1.6590 | **12.2444%** | **0.232** |
| 仅本底（M 处换回 CPU） | 1.7087 | **52.5296%** | **0.994** |

## 判据 1：🔴 **弥散本底是主因，H-outlier 被否定**

`R_base/R_all = 0.994 > 0.7` 且 `R_out/R_all = 0.232 < 0.3`，命中"弥散本底是主因"分支。

⇒ **下一步转向全局精度配置，不要再纠结 ch85。**

## 判据 2（自洽性）：✅ 通过
`sqrt(R_out² + R_base²) = 53.9378%` vs `R_all = 52.8711%`，比值 **1.020**
⇒ 近似可加，part2 对该扰动基本线性，归因结论可信（非线性放大不构成干扰）。

## 判据 3（能量占比复核）：❌ 原②推论被推翻
M（前 16 个极端点）占 `||U_htp − U_cpu||²` 的 **64.28%**，
而 HANDOVER 15.8 节估的是 "~81%"。**该估算不成立，已在文档中标注更正。**

## 结论的意义（为什么这个实验非做不可）

那 16 个点占**输入**误差能量的 64%，却只造成 23% 的**下游**损害；
弥散本底只占 36% 的输入能量，却造成 **99%** 的损害。
**"误差能量占比"与"下游致害程度"严重不一致。**

若跳过因果分离、直接按能量占比归因，就会一头扎进 ch85 / 量程上界这条错路。
这正是 CLAUDE.md 约束 2 与 MAINLINE 规则 1 反复强调的"差异≠根因"。

## 附带的量级事实（①实测，指向下一步）

`unified` 的量化 scale = **0.0978**，而 HTP vs CPU 的弥散差异
p50 = 0.373（≈ **3.8 个量化步**）、p90 = 1.21（≈ **12.4 个量化步**）。

⇒ 弥散差异**远大于舍入量级**（纯舍入应 ≤ 0.5 步）。
⇒ 这不是"量化表示"的差异，是**计算过程**的差异
   （算子实现 / 累加精度 / 中间重量化策略）。
