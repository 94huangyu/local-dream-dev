# EXP_PLAN_VAE_LAYER —— #77：×1.3324 的增益在 VAE 的哪一层累积？

定稿时间：**2026-08-21**（执行前定稿，**判据不得事后修改**）
前置：#78（`EXP_PLAN_VAE_GAIN.md`）已确定缺陷 = **全局增益 ×1.3324（76%）＋ 边缘性结构残差 9.86%**

---

## 一、为什么这样设计（两条都来自已实测的教训）

1. **不按序匹配 `group_norm`**。上一次 `vae_layerwise.py` 正是栽在这：
   ONNX 里 GroupNorm 被分解成 `Reshape→InstanceNorm→Reshape→Mul→Add`，
   中间形态是**展平的**，与 PyTorch 模块序对不上（第 2 个即 `(1,512,128,128)` vs `(1,512,16384)`）。
   ⇒ **改用 `Conv` 作锚点**：两侧都是 35 个、都是 4 维、**不被 Reshape 分解**，且天然把每个
   GroupNorm/SiLU 夹在两个 Conv 之间。
2. **不测高频能量**。#79 已证明该量主要在反映全局增益，用它会重复同一个错误。
   ⇒ **主量改为逐层输出 `std` 之比**（尺度不变、单标量、形状错位立即暴露）。

## 二、实现路径

- **PyTorch 臂**：hook `vae.decoder` 里全部 `nn.Conv2d`，按调用序记录每个输出的
  `mean/std` 与一份**固定随机子样**（每层 ≤100k 元素，种子由 `(层号, 元素数)` 决定 ⇒ 两侧完全一致）
- **ONNX 臂**：取 `graph.node` 里全部 `op_type=="Conv"` 的输出（ONNX 保证拓扑序），
  加为 graph output，**分批**运行（高分辨率层单张达 1 GB，一次全取会打爆内存）
- 两侧只保留统计量与子样，**不保留完整张量**

## 三、🔒 判据（事前锁定）

### V 门（有效性，先过，不过则作废）

| 门 | 要求 |
|---|---|
| **V1 数量** | 两侧 Conv 数量相等（期望 35） |
| **V2 形状** | **逐个 index 形状完全相等**，任一不等 ⇒ 匹配错位，**立即停止**（上次正是这条断言救的场） |
| **V3 端点** | 最末 Conv 输出的 `std` 之比 = **1.3324 ± 0.02**（该输出就是 `pixels`）<br>⚠️ 这条同时**兜住"加 graph output 抑制了 ORT 融合、从而改变数值"**这个风险 |

### 主判据 A：增益的累积形态

令 `r_i = std_onnx(i) / std_pt(i)`，`q_i = r_i / r_{i-1}`（`r_{-1} := 1`）：

| 结果 | 判定 | 后续 |
|---|---|---|
| 存在 `q_i ≥ 1.10` | **单点跳变** | 定位到该层，直接查该层前的算子 |
| 全部 `q_i < 1.05` 且 `r_i` 基本单调上升 | **均匀累积** | 指向归一化层的普遍性数值问题（③ 假设成立方向） |
| 其余 | **混合** | 报 top-3 跳变层，逐个查 |

### 主判据 B：结构残差的引入点

每层在子样上做最小二乘仿射 `onnx ≈ a·pt + b`，取残差相对 L2 `s_i`：
**第一个满足 `s_i ≥ 3%` 的 index** 即结构残差引入点。
（端点参照：成图上该残差为 9.86%）

⚠️ 按约束 7：报 `s_i` 时同时报分母的前 1% 能量占比；>50% 则另报主体口径。

## 四、失败归因

- V1/V2 不过 ⇒ **锚点选择错误**（不是方向错），改锚点重来
- V3 不过 ⇒ **测量行为改变了被测对象**（加 output 抑制融合），改用不加 output 的方案（如逐段切图）
- 三门全过但 `r_i` 全程 ≈ 1.0 直到最后一层才跳 ⇒ 增益来自 **`conv_out` 之后**，
  即 `to_img` 之前的某一步，需回查导出脚本的后处理

## 五、【2026-08-21 执行中】🔴 第一次运行作废：V2 门（形状相等）分辨力不足

**现象**：V1/V2/V3 三门全过，但 Conv#0 的 `std` 之比 = **2.7595**。
Conv#0 是 `conv_in`，**权重逐位相同、输入逐位相同 ⇒ 输出必须逐位相同**，比值必须是 1.0000。
中段残差 `s` 达 55%~90%（按约束 7 已属「已毁」区间，两侧张量已去相关）。

**根因（不是方向错，是操作化错）**：Conv 0~10 的输出**全部是 `(1,512,128,128)`**
⇒ 「逐个 index 形状相等」这条断言在本图里几乎没有分辨力，
**错位也能全过**。这与上次 `vae_layerwise.py` 的失败是**同一类错误**：
把一个弱条件当成了对应关系的充分判据（约束 8）。

**⇒ 第一次运行的全部逐层数字作废，不得引用。**
（V3 之所以过，是因为 Conv#34 形状 `(1,3,1024,1024)` 唯一，那一个确实对上了。）

### 五·1 改正：锚点从「激活形状」换成「**权重字节**」

文档已确立**73 个权重逐位吻合**（HANDOVER 15.21.3）⇒ 用权重字节的哈希做匹配，
得到的是一个**无歧义双射**，**完全不依赖任何顺序假设**（既不依赖 ONNX 节点序，
也不依赖 PyTorch 模块调用序）。

**新 V2 门**：
- V2a：每个 ONNX Conv 的权重哈希，必须在 PyTorch conv 权重哈希集合里**恰好命中一次**
- V2b：匹配必须是**双射**（35↔35，无重复、无遗漏）
- V2c：配对后形状仍须相等（保留原断言作为二次校验）
- **V2d（新增·补分辨力）**：`conv_in` 对应层的 `std` 之比必须 = **1.0000 ± 0.001**
  —— 这是一个**已知答案的样本**（权重与输入都逐位相同），用它验证整条测量链本身成立（约束 8）

### 五·2 顺带修一个会污染残差的实现缺陷

原 `sub_idx(i, n)` 的随机种子**依赖层号 `i`** ⇒ 一旦两侧配对不是 `i↔i`，
两侧取的就是**不同的元素子集**，残差 `s` 完全无意义。
⇒ 改为**只依赖元素数 `n`**（配对张量的 `n` 必然相等）⇒ 与配对顺序无关。
