## 一、这条线索怎么来的（不是凭空提出）

复现 #97 时 V3 门 3/4 未过。诊断链：

1. ONNX 实查：Pow 指数 2.0、eps 1e-05、ReduceMean `axes=[-1] keepdims=1` ⇒ 公式三个假设全对
2. 逐通道最小二乘拟合 `y=(x/rms(x))*g_eff` ⇒ 残差 **0.0001%** ⇒ 结构精确，偏差只在 gamma
3. CPU 参考跑的是 `transformer_part1b_quantized.dlc` 且未加 `--enable_cpu_fxp`（#35）
   ⇒ **浮点执行量化 DLC** ⇒ 运行时 gamma = 反量化后的量化 gamma
4. DLC encoding 实查：**gamma 是 `uFxp_8`，8-bit，per-tensor**
5. 用 DLC 的 encoding 做 Q/DQ 后重跑 ⇒ **V3 门 4/4 全过**（0.0001%/0.0001%/0.0000%/0.0632%）

副产物即本线索：**8-bit gamma 向 RmsNorm 输出注入的表示误差**（输出域 bulk 口径）
= **1.3085% / 1.5508% / 1.4510% / 0.1785%**。

### 为什么值得查（量级对比）

| 张量 | 8-bit 量化向输出注入（输出域） |
|---|---|
| FC 权重 `val_1800`（**已被 #47 per-row 优化过**） | **0.5050%**（§15.26 C 臂） |
| RmsNorm gamma（per-tensor，**从未被优化**） | **1.31% / 1.45% / 1.55%** |

结构原因：FC 权重误差在 K=3840 的求和中按 ~√K 平均掉；
**gamma 是逐元素相乘，不发生平均** ⇒ 单位比特杀伤力天然更高。

## 二、预期结果 / 实现目标

**目标**：在**不重量化、不占设备**的前提下，量出「gamma 8-bit」这一项在
**端到端 step-0 噪声预测**上相对 FP32 的贡献 `E_gamma`，用于决定
「下一次重量化要不要把 gamma 提精度」。

**这是最小确认，不是完整验证**。完整验证必须重量化 + 建 context + 上机（6h + 设备）。

## 三、实现路径

三段 FP32 ONNX 链（`part1a → part1b → part2`），复用 `scripts/fp32_noise_ref.py`
的**同一套输入与同一条代码路径**（同 seed / caption / timestep，与设备 step-0 逐字节相同）。

- **A 臂（装置门）**：原始 ONNX，未改。输出必须复现已存的 `vs_fp32/latents_fp32_s0.raw`
- **B 臂**：仅把 **205 个 RmsNorm gamma**（part1a 71 / part1b 44 / part2 90）
  按量化器规则 Q/DQ 回 float32，其余**一字节不动**

gamma 的定位用**结构检测**（`Mul(A, init)` 且 `A = Mul(x, Reciprocal(...))`），
**不靠张量名**。已知样本校验：part1b 检出 **44** 个，与 #13 实测的「44 个 norm」吻合。

改法：只把这 205 个小张量**内联**进新 `.onnx`，其余初始化器保持外部引用；
新文件写进**同一目录** ⇒ 相对 `location` 仍有效，**不重写 13.7 GB 外部权重**。

### encoding 规则（🔒 已通过已知样本门，4/4）

```
lo = min(min(x), 0) ; hi = max(max(x), 0)
scale  = float32((hi - lo) / 255)        # 🔴 必须 float32；用 float64 会系统性偏
offset = round(lo / scale)
q  = clip(round(x/scale) - offset, 0, 255) ;  dq = (q + offset) * scale
```
对 4 个从 DLC 实取的 encoding 复现：相对差 2e-11~1e-11，offset 逐个精确 ⇒ **PASS 4/4**。
（约束 8：先用已知样本验证操作化，再写进方案。第一版用 float64 算 scale，**未过**。）

## 四、🔒 判据（事前锁定，不得事后修改）

### 度量

`E_gamma` = step-0 噪声预测 **全量相对 L2**，原点 `vs_fp32/latents_fp32_s0.raw`。
全量口径合法性依据 §3.1：该张量能量集中度仅 **8.15%**。
⚠️ 按约束 7，**必须同时报告前 1% 元素占 ‖a‖² 的比例**；若 >50% 则改用主体口径。

### 参照刻度（已有实测）

**15.99%** = CPU 参考（全部权重 8-bit 量化、激活浮点）⇒ 这是**纯权重量化地板**
**44.80%** = 当前四段 per-row 端到端｜**47.07%** = 橙色色块

### 决策判据

令 `share = (E_gamma / 15.99)²` = gamma 占**权重量化地板能量**的比例。

| 结果 | 判定 | 后续动作 |
|---|---|---|
| `E_gamma ≥ 7.15%`（share ≥ 20%） | 🟢 **主要成分** | 值得**专门**跑一轮完整验证（重量化+建图+上机） |
| `2.26% ≤ E_gamma < 7.15%` | 🟡 **次要但非零** | **捆绑**进下一次为其他 P1 而做的重量化（边际成本≈0），不单独立项 |
| `E_gamma < 2.26%`（share < 2%） | 🔶 **低优先** | 登记为【未查·低优先】，本轮不投入 |

🔴 **无论落哪一档，都不得写「已排除 / 已证明无效」。**
理由：#52 实测 **HTP 对权重量化步长的敏感度 = CPU 的 37.6 倍**，
本实验是**宿主浮点**测量 ⇒ 只是 HTP 影响的**下界**。
#9 正是「用表示误差论证关闭」而后被 #52 动摇，**不重复该错误**。

### V 门

- **V0（装置门 / 已知答案样本）**：A 臂输出 vs 已存 `latents_fp32_s0.raw`
  相对 L2 **< 0.01%**。不过 ⇒ 我的执行环境与产生原点的那次不同，**整个实验作废**。
  （#80/#82 教训：先跑已知答案的样本再谈结论。）
- **V1（单变量门）**：B 臂模型与 A 臂逐初始化器比对，**差异必须恰好是那 205 个 gamma**，
  其余全部逐字节相同。不过 ⇒ 不是单变量，作废。
- **V2（操作化门）**：encoding 规则复现 4 个 DLC 实取样本 —— **已 PASS 4/4**（见 §三）
- **V3（口径门）**：报告 FP32 参考张量前 1% 能量占比；>50% 则全量口径失效，改主体口径
