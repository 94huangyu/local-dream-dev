## 3. 要测的三个环节（各自单变量）

### G-E · 文本编码器（我们的 ONNX TE vs 官方 Qwen3Model）

**现有唯一数据**：20-token 情形 **相对 L2 0.8628%**（`official_pipeline_run.py` 头部），
**22-token 无独立校验，当前部署的 L=80 从未验证**。

- **做法**：同一份 `prompt_ids.npy`（22 个真实 token，补到 L=80），
  分别过我们的 ONNX TE 与官方 `Qwen3Model`，比 caption 张量。
- **口径**（约束 7）：报全量相对 L2 **+ 前 1% 元素占 `‖a‖²` 的比例**；
  若集中度 > 50% 则必须同时报主体口径（`|a| ≤ p99`）与主体余弦。

### G-T · Transformer 实现（**本方案的主判据**）

- **做法**：**两臂喂完全相同的输入** —— 同 `latents_cxx_seed42.raw`、
  **同一份 caption 张量**（用我们的 TE 输出，使 G-E 的差异不混进来）、同 timestep(step 0)。
  官方臂 = `official_pipeline_run.py` 的 transformer（bf16，单步）；
  我们臂 = `t2_fp32_ref.py step` 的四段 ONNX 链。
- **取噪声预测**：我们臂写出的是更新后的 latents，按其自身的 Euler 式
  `nxt = lat − dt·noise` 反解 `noise = (lat − nxt)/dt`（dt 由已验证的调度器给出）。
- **口径**：同 G-E。⊕ 该张量的能量集中度历史值 **8.15%** ⇒ 全量口径合法（§3.1），
  但仍**必须现算并报出**，不得沿用旧值。

### G-A · `stack_1` 轴 0 = 33（#154，唯一**已确认**的算法不一致）

- **做法**：官方 PyTorch 内单变量 A/B，只切图像块位置起点 **33 vs 80**，其余全同，比成图。
- ⚠️ 只有 G-T 判 🔴 或 🟡 时才做；G-T 若 🟢 则说明 transformer 实现等价，
  33 这个值即便不同也没有在 step-0 表现出来，届时改为查累积效应。

## 4. 判据（事前锁定，不得事后修改）

**标尺的来历**：step-0 噪声预测的相对 L2 是本项目**唯一有刻度**的尺子（§3.1）：
**15.99% ⇒ 成图完好｜44.80% ⇒ 清晰的猫｜47.07% ⇒ 橙色色块**。
量化造成的同口径误差是 **21~44%**。因此判据按「相对量化误差的量级」定：

| 门 | 量 | 🟢 | 🟡 | 🔴 |
|---|---|---|---|---|
| **G-T** | 两臂 step-0 噪声预测相对 L2 | **< 1%** | 1% ~ 5% | **≥ 5%** |
| **G-E** | 两臂 caption 相对 L2 | < 0.1% | 0.1% ~ 1% | ≥ 1% |

**判读规则（同样事前写死）**：

- **G-T 🟢** ⇒ transformer 实现**等价**。则 22.47 dB **不可能**主要来自 transformer
  ⇒ 差异来自 TE（看 G-E）、VAE、或 8 步的混沌累积。**主线 A 的方向要改**，
  且必须补做「混沌 vs 缺陷」的判别（见 §5）。
- **G-T 🟡/🔴** ⇒ 实现有实质差异 ⇒ 逐段定位（part1a→1b→2a→2b 依次比中间张量），
  并把 #154 的 A/B 提到最前。
- 🔴 **无论结果如何都不改判据。** 若结果落在门的边界附近，按更严的一档处理。

## 5. 🔴 必须同时回答的一个问题：22.47 dB 是「缺陷」还是「混沌」

这两者的处置完全相反，**不能靠猜**。

**现有的间接证据（②推论，不是实测）**：#158 实测把初始噪声扰动 **1e-6 量级**
（27% 元素差 1~2 ULP，RMS 1.9e-6），走完 8 步 FP32，成图 **86.52 dB**，
314 万像素只有 456 个不同。而我们 vs 官方是 **22.47 dB**，差 **64 dB**。
⚠️ **但「扰动输入」与「换实现」不等价**，该推论**不得当结论用**。

**判别方法（本方案内可做）**：G-T 的 step-0 相对 L2 就是判别量 ——
step 0 尚未经过任何累积，若两臂在 step 0 就差 ≥1%，那是实现差异；
若 step 0 差 <0.01% 而成图差 22 dB，那才是混沌放大。

### 🔴 途中差点报出的假警报（记下来）

第一版比较给出 **198.5577%、余弦 −0.9879** —— 两个张量几乎互为相反数。
**没有直接报「实质不一致」，而是先查已知样本**：step-0 之后的 `latents_std`，

（官方 `noise_pred = −model_out` 配 `sample + dt·out`；我们 `nxt = lat − dt·noise` 且 dt 为负），
**不是数值分歧**。对齐符号后才是 15.5172%。
⇒ **口径/约定必须先用已知样本验证**（约束 8）。

### 误差结构（用于定位）

## G-A · 位置编码 —— ⚠️ **实验空转（无变量），但查清了事实**

**结果：官方传给图像的 `pos_start` 本来就是 (33,0,0)，与我们的 `stack_1` 轴0 = 33 相同。**
`parity_pos33.py` 的生效门直接打印出了这一点 ⇒ 实验无变量，其输出的 198.56%
是该脚本漏了符号对齐（`parity_compare.py` 里有），**不是有效数字**。

🔴 **我的错**：我从 `patchify_and_embed_omni` 推出「官方 = 23」，
而实际调用的是 `patchify_and_embed`——
```python
cap_len = _pad_with_ids(cap_feat, (n + (-n) % 32, 1, 1), (1,0,0))[3]   # 补齐后的长度
img_pos_start = (cap_len + 1, 0, 0)
```
22 token ⇒ 补齐 32 ⇒ **33**。**官方的约定是「补齐后长度 + 1」，不是「真实 token 数 + 1」。**

⇒ **G-T 的 15.52% 与位置编码无关**（本 prompt 下两边位置相同）。

⇒ 但**另一个真缺陷因此浮出**（已登记 #166）：官方随 prompt 变
（≤32 ⇒ 33｜33~64 ⇒ **65**｜65~80 ⇒ **97**），我们**恒 33**。
Tier 2 的上限是 72 个内容 token，#143 的「黄铜罗盘」（43 内容 token）就落在错误区间。
③其对成图的影响未测。
