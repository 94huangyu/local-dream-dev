# 如何真正掌握 DLC 执行契约（不靠"更小心"，靠机制）

## 0. 先定义问题：我失败的模式是什么

不是"不够仔细"，是一个**系统性模式**：

```
用 ONNX 的知识推断 DLC 行为  ->  只有报错时才发现不符  ->  只修报错的那一处
                                        ^
                                        |
                            如果 snpe 不报错（静默失败），
                            这个环节根本不会触发
```

已经发生的 6 次（全部是"撞了才查"）：
Bool_8 字节宽、`latents_shape` 不在 DLC 里、输出一律 float32、`add_24/add_45` 被融合、
`--onnx_skip_simplification` 无效、以及最危险的一次——**输入尺寸不对时 snpe 不报错，
只把所有输出按比例缩小 4 倍**。

所以"掌握"必须满足三条，缺一不可：
1. 契约是**查出来**的，不是回忆或推断出来的；
2. 每次喂数据都被**自动**校验，不依赖我当时是否想起来；
3. **静默失败被转成响亮失败**——这是最关键的一条。

## 1. 四层机制

### L1：机器可读的契约（唯一事实来源）
产出 `dlc_contracts.json`，覆盖全部 8 个 DLC：
每个输入/输出的 名称、DLC声明类型、shape、元素数、**宿主侧应写/应读的字节数**。
由 `snpe-dlc-info` 转储自动生成，**不手工维护、不从 ONNX 推导**。

> 防的是：规则 3（DLC 输入集合 ≠ ONNX 输入集合）、规则 4（张量名被融合改变）。

### L2：唯一的调用入口（不能绕过）
所有跑 DLC 的代码统一走 `snpe_runner.py`，禁止各脚本自己拼 input_list、自己写 .raw。
该模块强制做：

| 检查 | 拦截的具体错误 |
|---|---|
| feed 的键集合必须**恰好等于**契约的输入集合 | 多喂 `latents_shape`（part2 曾因此失败） |
| 每个输入按契约字节数写，写完 assert 文件大小 | Bool_8 写成 uint8 导致 1/4 批次 |
| 请求的输出名必须在契约里（或在 encoding JSON 名单里） | 请求 `add_24` 这类被融合掉的名字 |
| **跑完后 assert 每个输出的字节数 = 元素数 × 4** | **静默缩批**（唯一能抓住它的检查） |

> 关键点：把"我要记得检查"变成"不检查就跑不起来"。

### L3：黄金回归测试（验证我的理解本身是否正确）
`test_contract_golden.py`：用固定输入跑 part1a，断言若干输出的统计量与**历史独立测量**一致。
基准：第 8.4 节记录的 `add_54` 误差 31.8（那次测量与本次实现完全独立）。
偏差 > 5% 即判定"我的调用方式有问题"，而不是"模型有问题"。

> 防的是：我把管道接错了却浑然不觉。任何一次改动 runner 之后必须先过这个测试。

### L4：未知项清单 + 逐项受控实验
`../docs/EXECUTION_MODEL.md` 第四节列了 5 个未知项。规则：**清单里的任何一条，在被受控实验关闭之前，
不得作为事实使用**。每关闭一条要写明实验设计和实测结果。

## 2. 执行顺序与"完成"的定义

| 序 | 任务 | 完成判据 | 依赖 |
|---|---|---|---|
| 1 | 生成全部 8 个 DLC 的 `dlc_contracts.json` | 8 个 DLC 全部有条目，且与已知的 3 个人工核对一致 | 无（可与 Test B 并行） |
| 2 | 实现 `snpe_runner.py`（含 L2 四项检查） | 用它重跑一次历史实验，结果与历史一致 | 1 |
| 3 | 黄金回归测试 | `add_54` 误差复现 31.8 ± 5% | 2 |
| 4 | 关闭未知项 ③：`--use_native_input_files` 语义 | 受控实验：同一输入分别用/不用该 flag，对比输出 | 2 |
| 5 | 关闭未知项 ⑤：输入**大于**期望时的行为 | 受控实验：喂 2× 尺寸，记录实际行为 | 2 |
| 6 | 关闭未知项 ①②：CPU 参考 vs HTP 等价性、`.bin` 契约 | **需要真机**，先写出实验设计 | 手机 |

## 3. 怎么"确保"，而不是"承诺会小心"

1. **把规则写进 `CLAUDE.md`**：禁止绕过 `snpe_runner.py` 直接拼 input_list / 写 .raw。
   下次会话加载项目时自动生效。
2. **契约由脚本生成**，不手工维护 → 不会因为我记错而失同步。
3. **L2 的检查是硬断言**，失败即抛错 → 不依赖我当时的注意力。
4. **L3 黄金测试**每次改 runner 后必跑 → 我对契约的理解如果错了，会立刻暴露。
5. **未知项清单是显式的**：文档里凡引用第四节的内容，必须标注"未验证"。
   这条已经写进 `CLAUDE.md` 约束 2。

## 4. 一条我无法单靠离线工作关闭的项

**CPU 参考（`snpe-net-run` 跑 `.dlc`）与 HTP（真机跑 `.bin`）是否数值等价。**

在真机验证之前，所有离线结论的表述必须是 **"在 SNPE CPU 参考实现上"**，
不得写成"设备实测"。13.9～13.17 现有的措辞需要按此修正。
