## 2. 门（按顺序，前一道不过不进下一道）

### G-SPILL（宿主，零设备）——**必须在投入建图前过**
1152×864 就是死在这里（part2a spillFill **999 MiB**），当时没筛先建，白烧数小时。

- 判据（沿用 `geom_sweep.py` 已定稿的）：**spillFill < 400 MiB 且 预测 ION ≤ 2289 MiB**。
- 已有实测：1:1 N=4176 → 276.9 MiB ✅；4:3 N=4224 → **269.1 MiB** ✅；16:9 N=3680 → **249 MiB** ✅。
- 🔴 **「part2a 的 spill-fill 只看 N」这条操作化必须先用已知样本验证**（约束 8）：
  3:4 与 4:3 同 N=4224，若 3:4 建出的 part2a spillFill **与 4:3 的 269.1 MiB 同值**，
  该操作化成立 ⇒ 才允许用它把 16:9 的 249 MiB 推广到同 N 的 9:16。
  **若两者不同值 ⇒ 该推广作废，9:16 必须单独跑 `geom_sweep.py`。**

### G-RANGE（宿主，约 5 分钟/比例）——只能否决不能放行
新比例复用 1:1 的 encoding，激活若超量程会被钳。
- 判据：`实测|max| / 部署 encoding max` ≤ 1.00 🟢 ／ ≤ 1.10 🟡 记录 ／ > 1.10 🔴 首要嫌疑。
- 4:3 当时最大比值 **1.000**。⚠️ 本门**不能放行**（指南 §41）：不超量程 ≠ 画质没问题。

### G-QUANT（宿主）

显式 `-s`、`--use_per_channel_quantization`、`--config_file`（#95，漏了会静默编成 dspArch 68）。

### G-QUALITY（设备，约 1 小时/比例）——**验收门**
沿用 D2 的形式与判据，**不因为 4:3 过了就跳过**。
- 做法：两臂同解码路径，每臂 **n=3 个 seed**（42/43/44）。
  🔴 **参考文件必须按 seed 隔离命名**——2026-09-03 就是固定名被覆盖，
  导致「本 seed 的量化输出 vs 另一 seed 的 FP32 参考」，落在 12 dB 的无关图基线上，
  害我报出「换比例回退 9.61 dB」的错误结论。缺文件一律跳过该臂，**绝不退回固定名**。
  另加 md5 互异门：三个 seed 的参考文件 md5 必须两两不同。
- 判据：`D = PSNR(1:1) − PSNR(新比例)`，取三 seed 均值。
  **D ≤ 2.0 dB 🟢 通过**／2~5 🟡 需看图判断／> 5 🔴 须查。
- 🔴 **绝对值不得单独作判据**（#143：同一套量化在三个 prompt 上 22.58/14.25/13.47 dB，跨度 9 dB）。
- ⚠️ 约束 1：**两臂的图都必须自己打开看**，不得只看 PSNR。

### G-MG（设备）——**多图 context 的完整 8 步验证，本项目尚欠**
今天交付 4:3 用的是**单图** context，因为多图只过了 D1 的装载/执行。
B 形态（共享权重，约 12 GiB / +15%）成立的前提就是这一门。
- 做法：把 5 个比例合成每段一个多图 context（`weight_sharing_enabled` + `ENABLE_GRAPHS`），
  在设备上跑**完整 8 步**，与同比例**单图** context 的终点 latents 比。
- 判据：**逐元素最大绝对差 = 0**（同一份量化权重、同一图，多图容器不应改变数值）。
  非零 ⇒ 多图容器引入了数值差异，B 形态**不得交付**，退回单图形态（体积代价 +62%）。
- 🔴 顺带必须验的：PD 只计 enable 的图（#86 生死线）在**五图**下仍成立
  ——已验过的是**两图**，不得直接外推（约束 4·补：机制从 A 迁到 B 要先验迁移本身）。

## 3. 失败时怎么区分方向错 vs 执行错

| 现象 | 先查 | 依据 |
|---|---|---|
| 建 context 失败/OOM | 是不是又并行跑了重活 | 宿主 23.7 GB，单个建图进程就占 10.6 GB，已压死过两次 |
| 设备 `0x3ea` | ENABLE_GRAPHS 有没有传 | #86 生死线：不传则整个 binary 反序列化，撞 PD 红线 |
| 设备 SIGSEGV in libQnnHtp | 传进去的 config 数组里有没有 `customConfig==nullptr` 的项 | #156 根因，`QNN_CONTEXT_CONFIG_OPTION_CUSTOM==0` |
| 画质塌 | 先看 G-RANGE 的比值，再看两臂参考文件 md5 是否互异 | 前者是 #53/#67/#110 一族；后者是 2026-09-03 的覆盖事故 |
| 报错指向某文件却查不出问题 | 该报错指向的对象是不是我实际验证过的那个 | 约束 11·再补「报错说谎」 |
