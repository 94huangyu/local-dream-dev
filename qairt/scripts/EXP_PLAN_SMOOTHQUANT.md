# EXP_PLAN_SMOOTHQUANT —— §6 的 E：把量化难度从激活迁到权重

**定稿：2026-08-30，执行前。判据事前锁定，不得事后修改（约束 4）。**

---

## 〇、为什么是它

这是**唯一一条既服务顶层目标（与 FP32 的一致性）、又不吃速度**的路。
你 2026-08-25 明确禁止再用速度换精度，而其他提精度的手段（扩 FP16 覆盖、加宽激活）
全都要吃速度或内存 —— 而内存刚被 F（四段全常驻，ION 峰值 9100 MiB、余 839 MiB）吃掉了大半。

**机理有实测支撑（#67）**：

```
权重  裁掉 0.0520% 的元素 → 只丢 1.12%  能量  ⇒ 权重不是离群值主导
激活  钳掉 0.0261% 的元素 → 丢掉 98.75% 能量  ⇒ 激活是极端离群值主导
```

⇒ 少数激活离群点把量程撑宽，占 99% 的主体只分到很少有效位。
SmoothQuant 对 `Y = X·W` 改写成 `Y = (X/s)·(sW)`（逐通道 `s`，数学等价），
把动态范围从激活挪进权重。**`s` 离线折进权重 ⇒ 运行时零额外算子 ⇒ 速度中性。**

🔴 **#20 的旧判决不构成否定**（2026-08-30 已订正两份台账的矛盾）：
它的依据是**量化表示误差**，而 #52 实测表示误差**不是** HTP 误差的预测量（37.6 倍）。
⇒ 结论的尺子不合格，得重判。**但这也不等于它有效。**

## 一、目标与预期

**目标**：用**最便宜**的手段判断 SmoothQuant 值不值得投入完整实现（估计 1 天以上）。

**预期**：③**无实证依据**。机理成立不等于在本模型上有效——
本项目已有先例：#53「收紧激活量程」机理听着对，代价门一算直接否决。

---

## 二、🔴 先过代价门 G0-cost（约束 4·补，宿主，零设备）

**在写任何实现之前**，先用**已有的 FP32 张量**回答一个问题：

> 逐通道迁移之后，**激活的纯表示误差降了多少？权重的纯表示误差涨了多少？**

做法：对若干个 FC 的输入激活 `X` 与权重 `W`，取逐通道 `s = max|X_c|^α / max|W_c|^(1-α)`
（α 是 SmoothQuant 的迁移强度，扫 α ∈ {0, 0.25, 0.5, 0.75, 1.0}），
分别做 quantize-dequantize 模拟，报**全量 + 主体两个口径**（约束 7）。

**否决条件（事前锁定）**：

```
若在所有 α 上，(激活表示误差的改善) 都小于 (权重表示误差的恶化)  ⇒ ❌ 直接否决，不做后续
若存在 α 使净表示误差改善 ≥ 20%（相对）                          ⇒ 🟢 进入 §三
介于两者之间                                                      ⇒ 🟡 记录，按 §三的成本再决定
```

⚠️ **这道门只能否决，不能肯定**：#52 已证表示误差不预测 HTP 误差。
过了门只说明「值得继续花钱」，不说明「会有效」。

**成本**：约 1~2 小时（宿主，零设备）。

## 三、若 G0-cost 通过：宿主 QDQ 全模型模拟（仍零设备）

用已建好的 `scripts/sim_qdq.py`（#124），**新增一个模式 `S`**：
按逐通道 `s` 缩放激活、把 `s` 折进权重，然后照常插 QDQ。

与现有模式对照（同一套装置，唯一变量是有没有 SmoothQuant）：

| 模式 | 含义 | 用途 |
|---|---|---|
| `H` | 当前部署配置（Clip + FP16 集合） | 基线 |
| **`S`** | `H` + SmoothQuant | 待测 |
| `C` | 权重 int8 + 激活 FP32 | 8-bit 权重的绝对上限 |

**判据（事前锁定）**：

```
S 的 E_all 比 H 改善 ≥ 15%（相对）  ⇒ 🟢 值得上设备
改善 5%~15%                          ⇒ 🟡 收益小于实现成本，记录后搁置
改善 < 5% 或变差                     ⇒ ❌ 关闭 E
```

⚠️ **划界（#124 自己写的，不得忽略）**：模拟与设备的比值只在**旧机制**上验证过 2 个点
（1.207 / 1.232），**只能用于排序与量级，不得当精确换算**；且 #121 已证 L1 无法换算成 L3
⇒ **模拟通过后仍必须实测 L3**。

**成本**：改模拟器 + 跑四段，约 3~5 小时（宿主）。

## 四、缺什么数据（**这是本方案最大的未知**）

🔴 **SmoothQuant 需要【逐通道】激活幅度，而本项目现有的 `<seg>_amax.json` 是【逐张量】的**
（实查 `part1a_L80_amax.json`：每个张量只有 `amax / med / p99 / conc1` 四个标量）。

⇒ 需要一次新的测量：**对喂给 FC 的激活，按特征通道求 max**。

- 范围可收窄：只需 FC 的输入，不是全部 918 个张量
- ①参照工时：本项目「逐张量 `|a|max` 全量测量」实测约 **55 分钟/段**；
  ③逐通道版本的成本**未测**，数据量更大但张量数更少，量级估计相当

**这一步必须在 G0-cost 之前完成**，否则 G0-cost 没有输入。

## 五、总成本与失败判据

| 阶段 | 成本 | 设备 |
|---|---|---|
| 逐通道激活统计 | ~1~4 小时（③未测） | 否 |
| G0-cost 代价门 | 1~2 小时 | 否 |
| QDQ 模拟（若过门） | 3~5 小时 | 否 |
| 真机验证（若模拟过） | 重量化+建图 ~70 分钟 + 设备 ~30 分钟 | 是 |

**⇒ 在碰设备之前，有两道门可以把它否掉。这是选 E 的主要理由：它的失败很便宜。**

### 失败归因（约束 4）

| 现象 | 是什么 | 下一步 |
|---|---|---|
| G0-cost 否决 | **方向无收益**（有 α 扫描作对照，满足 R1） | 关闭 E，顶层目标只剩 D 与「等新工具」 |
| G0 过、模拟不过 | 表示误差与端到端脱节（**与 #52 一致，不是新发现**） | 记录，搁置 |
| 模拟过、设备不过 | 模拟器适用边界问题（#123 已有先例：dtype 产物比值 1.826 离群） | 查机制，不得直接判 E 无效 |

🔴 **不得因一次不达标就写「SmoothQuant 无效」**（R1）：α 扫描本身就是对照组，
但结论只能覆盖**本模型、本配置、这几个被采样的 FC**。
