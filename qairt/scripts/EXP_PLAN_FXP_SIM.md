# EXP_PLAN_FXP_SIM —— 自建定点模拟器：HTP 做的是「正确的定点」还是「错的定点」？

定稿时间：2026-08-15（执行前定稿，判据不得事后修改）
主线归属：A → "如何解决 HTP 的数值问题"

## 0. 为什么需要它

外部评审指出并已确认：`snpe_runner.py` **从未使用 `--enable_cpu_fxp`**，
所有"CPU 参考"都是**浮点执行**（反量化后 float 计算）。
⇒ "HTP 比正确的 16-bit 实现丢 4 bit"**失去前提**——我们从来没有定点参考。

补测尝试也已失败（工具层面）：
```
error_code=703; CPU fixed point execution is selected with DLC having INT16 activation
```
⇒ SNPE 的 CPU 定点运行时**只支持 INT8**，本 SDK 拿不到 A16W8 真定点参考。

**因此自建。** 用 numpy 精确模拟单个 FullyConnected 的 A16W8 定点执行，
同时对比 FP32 与 HTP 实测输出。

## 1. 假设与分支

- **H-A：HTP 做的是正确的定点。** 模拟输出 ≈ HTP 输出。
  ⇒ 问题不在 HTP，而在**模型不适配 per-tensor A16W8 定点**。
  ⇒ 方向转为"让模型适配定点"（通道重缩放 / 混合精度），
     **通道迁移（台账 #20）应重开**。
- **H-B：HTP 做的是错的定点。** 模拟输出 ≈ FP32 而 HTP 明显偏离。
  ⇒ HTP 链路特有缺陷，继续按外部评审的门禁逐层排查。

## 2. 【本方案新增环节】先列出并验证"默认成立的前提"

本项目一天内被推翻的结论都源于**未验证的默认前提**
（度量口径、判据操作化、CPU 基线语义、FP16 必配 FP16 权重）。
因此本方案强制先列前提并逐条验证：

| # | 默认前提 | 验证方式 | 未通过时 |
|---|---|---|---|
| P1 | DLC 里 FC 的 STATIC 权重就是 ONNX 的对应权重（仅做了转置/重排） | 用 shape 匹配 + 反量化后与 ONNX 权重比对相对误差 | 找不到对应则该 FC 退出本实验 |
| P2 | FC 的语义是 `y = x @ W^T + b`（权重已 permute） | 用 **FP32 权重 + FP32 输入**复算，与 CPU 参考的 FP32 输出比 | 不符则先纠正算子语义再模拟 |
| P3 | 权重是 per-tensor 量化（单 scale/offset） | 已从 DLC 转储读到单值；再确认无 per-axis 字段 | 若实为 per-axis，模拟需按轴展开 |
| P4 | 输入激活按其自身 encoding 量化为 uFxp16 | 从 DLC 读该张量 encoding | 无 encoding 则用上游 Reshape 源 |

**P2 是关键**：若 FP32 复算都对不上 CPU 参考，说明我对算子语义的理解就错了，
后面的定点模拟毫无意义。**P2 不过则本实验立即终止。**

## 3. 模拟的实现路径

对每个 FC：
```
q_x  = clip(round(x/s_x) + z_x, 0, 65535)          # 输入 -> uFxp16
q_w  = clip(round(w/s_w) + z_w, 0, 255)            # 权重 -> uFxp8
acc  = (q_x - z_x) @ (q_w - z_w).T                 # 整数累加（int64，无溢出）
y    = acc * s_x * s_w + bias                      # 反量化
q_y  = clip(round(y/s_y) + z_y, 0, 65535)          # 输出 requant
y_hat= (q_y - z_y) * s_y
```
同时记录 **审查者 §3.8 的 offset 项**：
`主项 = Σ q_x·q_w`、`offset 项 = z_w·Σ q_x`，报告两者量级比。

再做一个**受限累加器**变体（acc 用 int32 并模拟饱和），检验"累加器溢出"假说。

## 4. 判据（事后不得修改）

度量按约束 7：主体（`|a| ≤ p99`）相对 L2 + 主体余弦 + 前 1% 能量占比。

**判据 0（前提）**：P1~P4 全部通过，尤其 **P2 的 FP32 复算相对误差 < 1%**。
不通过则本实验无效。

**判据 1（主判据）** 对每个 FC，记
`E_sim` = 模拟 vs FP32、`E_htp` = HTP vs FP32、`D` = 模拟 vs HTP：
- **`D` 显著小于 `E_htp`（`D < 0.3 × E_htp`）** ⇒ **H-A 成立**：
  模拟重现了 HTP 的行为 ⇒ HTP 做的是正确的定点，问题在模型/量化配置。
- **`E_sim` 明显小于 `E_htp`（`E_sim < 0.3 × E_htp`）且 `D ≈ E_htp`** ⇒ **H-B 成立**：
  正确的定点不该有这么大误差 ⇒ HTP 特有缺陷。
- 其余情况：按比例报告，不下单一结论。

**判据 2（offset 项）**：报告 `|z_w·Σq_x| / |Σq_x·q_w|` 的分布。
若中位数 > 1，说明 offset 修正项**主导**了整数累加 ⇒ 支持审查者 §3.8 的机制假说。

**判据 3（累加器）**：报告 `acc` 的实际取值范围与 int32 边界的距离。
若接近或超过 2^31，则"累加器溢出"假说得到支持。

## 5. 成功 / 失败判断

- **成功**：给出 H-A / H-B 的明确分支，并附 offset 项与累加器范围的实测。
- **失败·执行方法错误**：权重对应不上（P1）、语义不符（P2）、内存不足。
  ⇒ 修方法重跑，判据不变。
- **失败·方向错误**：模拟结果既不像 FP32 也不像 HTP ⇒ 我的定点模型本身写错了，
  必须先用一个**小规模已知样例**校验模拟器本身，再谈结论。

## 6. 预算

纯离线，无设备。5 个 FC，最大 [4128,10240]×[3840,10240]。
**注意内存**：整数矩阵乘会很大，需分块计算（按输出通道分块）。
