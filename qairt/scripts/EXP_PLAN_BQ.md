# EXP_PLAN_BQ —— #91：分块量化（BQ）在 HTP 上可行吗？值得吗？

定稿时间：**2026-08-22**（执行前定稿，**判据不得事后修改**）
试验台：P0-B 建成的单算子精确重放（`node_linear_99`，K=3840）

---

## 一、依据与预期

**机制依据**（#89 实测）：细化 scale 在消除 offset 之上还能再降 **20.7%**
（对称 per-tensor 0.8310% → 对称 per-row 0.6591%）。⇒ 比 per-row 更细可能还有收益。

**G0-cost（输出域，已算，约束 4·补）**：

| 配置 | 表示误差 | 相对 per-row |
|---|---|---|
| per-row（3840 scale） | 0.5051% | — |
| BQ block=128（115,200 scale） | 0.3635% | **−0.1416 pp** |
| BQ block=64（230,400 scale） | 0.3343% | −0.1708 pp |

事前定的线是"收益 <0.1 pp 不值得上机" ⇒ **block ≤128 过线**。

⚠️ **但预期收益小**，须事前写明以免事后自我说服：
per-row 的表示误差（0.5051%）**已经小于** HTP 超出误差（0.6591%）；
而 B→C 的经验是 scale 细化 2.68× 只换来 HTP 超出误差降 1.26×
⇒ **即使 BQ 完全兑现，算子级总误差预计只改善约 15%，端到端可能观察不到。**

⇒ 本实验的**主要价值在第一道门**：**HTP 到底支不支持 FC 的 BQ**。

## 二、🔒 判据（事前锁定）

### V0 支持性门（最有价值的一问）

`qairt-converter` → `qairt-quantizer` → `qnn-context-binary-generator` 三步全部成功，
且**读回 DLC 确认落地的是分块 encoding**（不是被静默降级成 per-row/per-tensor）。

| 结果 | 判定 |
|---|---|
| 任一步失败，或读回发现被静默降级 | ✅ **HTP/工具链不支持 FC 的 BQ** ⇒ #91 关闭，记录报错原文 |
| 三步全过且 encoding 确为分块 | 进入主判据 |

⚠️ **"静默降级"必须主动查**：#45 的教训是 overrides 失效时**不报错**。
判别方法：读回 DLC 看 `val_1800` 的 encoding 条目数与形态。

### 主判据（V0 过了才做）

令 `E_C = 0.6591%`（per-row，已实测），`E_BQ` = BQ 臂的 HTP 超出正确定点误差：

| 结果 | 判定 | 后续 |
|---|---|---|
| **E_BQ ≤ 0.85×E_C（≤0.560%）** | 🔴 **BQ 有实质收益** | 评估端到端可行性（模型体积、速度、PD 红线） |
| **E_BQ ≥ 0.95×E_C（≥0.626%）** | ✅ **无收益** | #91 关闭 |
| 中间 | 🔶 **边际收益** | 记录，**不推进**（端到端代价大于收益） |

### 其它 V 门（沿用 P0-B）

V2 输出字节数 63,406,080；V3 输入 md5 `eb9b583a0b41f8f37bfb69cc8077a9b5`

## 三、格式

`qairt-quantizer` **没有** BQ 的 CLI 开关（已读完整 `--help`）⇒ 只能经 overrides 注入。
用 schema **2.0.0**（#85 臂 B 已验证该通路可用）：

```json
{"name": "val_1800", "output_dtype": "int8",
 "y_scale": [[...], ...],      // [通道数][块数]
 "y_zero_point": [[0, ...], ...],
 "axis": 0,                    // BQ 时 axis = 分块所沿的轴
 "block_size": 128}
```

⚠️ 官方 Appendix C 的 BQ 例子**全部用 `int4`** ⇒ **int8 下是否支持未知**，这正是 V0 要答的。
⚠️ 2.0.0 是**整份文件的 schema**，激活也要用 2.0.0 写法
（`y_zero_point = -offset`，文档：*"Internally this is stored as offset = -y_zero_point"*）。

## 四、失败归因

- V0 因**格式写错**失败（报错指向 JSON 解析）⇒ 执行方法错误，修格式重试
- V0 因**后端不支持**失败（报错指向 op/backend）⇒ **方向结论**，#91 关闭
- 两者必须从报错原文区分，**不得含糊**（约束 11·再补：报错会说谎，先问它指向的对象对不对）
