# EXP_PLAN_ACTBF16 —— #103：激活用 **BF16**（part1b 试点）

定稿时间：**2026-08-22**（执行前定稿，**判据不得事后修改**）
线索：**#103**（#102 失败后的直接后继）

---

## 〇、🔴 我推翻了自己的止损，理由写在这里

`EXP_PLAN_ACTFP16.md` §六 明写「落 ❌ ⇒ 关闭 #102，**不做 BF16**」。**本方案推翻该条。**

**推翻理由**：那条止损写于**不知道失败模式**时，目的是防止"一条条换花样试"。
实际失败原因已被**精确诊断**：`Pow(x,2)` 在 FP16 里溢出（44 个 RmsNorm 输入中 37 个、part2 中 81/90 超标）。
**BF16 不是"另一个花样"，而是针对该诊断结论的直接解**——其指数范围同 FP32。

**不是无视止损**：本方案重新定稿判据与止损，并把推翻动作明写在案（约束 2：结论被推翻时保留原文并标注理由）。

## 一、G0-cost 代价门（约束 4·补）——**已过**

| | 全量 | **主体** | 动态范围 |
|---|---|---|---|
| uFxp_16 min-max（当前部署） | 0.1864% | **4.4741%** | — |
| FP16 | 0.0167% | 0.0209% | 🔴 `x²=5.68e10` 溢出（#102 死因） |
| **BF16** | **0.1315%** | **0.1675%** | ✅ `BF16(238418²)=5.69e10` 有限 |

⇒ BF16 主体表示误差比 uFxp_16 **好 26.7 倍**；全量 0.1315% **远低于**端到端 7.87% ⇒ **不否决**。

## 二、装置（相对 #102 的唯一变化）

```
qairt-converter  ... --float_bitwidth bf16      # ← 唯一变化（#102 是 16）
qairt-quantizer  ... --keep_weights_quantized --enable_float_fallback   # 不传 --float_bitwidth
```
🔴 文档实查：**converter 的 `--float_bitwidth` 接受 `32 / 16 / bf16`；quantizer 的只接受 `32 / 16`。**
#102 实测证明浮点类型由 converter 决定（quantizer 未传该参数，产物仍是 Float_16）。

**overrides 简化**：BF16 范围足够 ⇒ **不需要钉任何激活张量**（#102 钉了 6 个 FC 的输入+输出共 24 个名字）。
overrides 只含权重与 gamma 的 param_encodings，逐字取自现有 per-row DLC。

context 构建照抄参照臂配方（只有 `devices`，无 `graphs` 段；必带 `--config_file`）。

## 三、🔴 变量不纯（沿用 #102 §三·补，同样成立）

gamma(44) 与 bias(51) 会被连带浮点化（gamma 是**后端强制**：RmsNorm 无「定点权重+浮点激活」行）。
⇒ 结论措辞只能是「**这一组改动**」，不得说成「激活 BF16」。

## 四、🔒 判据（事前锁定）

| 门 | 内容 | 不过怎么办 |
|---|---|---|
| **G1 注入门** | 读回产物：激活为 **BFloat_16**，权重仍 `sFxp_8`/per-row 409600 条 | 修一次，仍不过则关闭 |
| **G2 容量门** | context 建得出且**不报 `Failed to find available PD`** | 🔴 撞红线 ⇒ **直接关闭，不调参** |
| **G3 装置门** | `--expect-arch 79 --expect-vtcm 8`，并与参照臂 `--diff` | 修一次 |
| **G4 数值门** | 输出 `unified` **无 inf/nan** | 有 ⇒ 记录并关闭 |

**主判据**：`unified` 相对 FP32 参考的**主体余弦**（约束 7：`unified` 集中度 99.83% ⇒ 以主体为准）。
**对照 = 今日同装置实测的 per-row：主体余弦 `0.7986`，全量 `7.8665%`**（不引用历史数字，#95）。

| 结果 | 判定 | 后续 |
|---|---|---|
| 主体余弦 **> 0.90** | 🟢 显著改善 | **立刻推进 part2**，不得在 part1b 继续打磨 |
| 0.80 < 余弦 ≤ 0.90 | 🟡 有改善 | 评估四段全做的性价比 |
| 余弦 ≤ **0.7986** | ❌ 无改善或倒退 | 关闭 #103 |

**并行硬约束**：`t_bf16 > 3 × t_perrow` ⇒ 🔴 产品级不可行（依据 #16）。

⚠️ **容量预警**（#102 实测）：FP16 版 context 1.56 GB + spillFill 1.22 GB = **2.78 GB**，
距 #57 红线 3.3 GB 只剩约 0.5 GB。**BF16 若同量级，part1b 能过但 part2 很可能撞门** ——
本试点须**记录 spillFill 实测值**，作为四段可行性的判断依据。

## 五、🔴 划界

- 只做 **part1b**；不得外推 part2 / 端到端 / 成图质量（#69/#70/#84：标量尺与成图反相关，最终须人工看图）。
- 表示误差改善 26.7 倍**不是**收益承诺（#52：表示误差不是 HTP 误差的预测量）。

## 六、止损

| 触发 | 动作 |
|---|---|
| 宿主 convert+quantize > **1 小时** | 停 |
| context > **2 小时** | 停 |
| G2 撞 PD 红线 | **直接关闭**，不调参 |
| 落 ❌ | **关闭 #103，本族（选择性浮点）全部关闭**，回 part2 算子级归因 |

**不得扩张**：不做 FP8/其他格式、不做其他段、不改权重量化、不调校准。
**本族到此为止** —— FP16 已死、BF16 若再死，则「把激活换成浮点」这条路整体关闭。
