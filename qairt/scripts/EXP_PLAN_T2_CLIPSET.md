> 状态：**执行前定稿（2026-08-28）**。判据锁定，不得事后修改。
> 归属：MAINLINE §6 **P1' Tier 2** 的强制前置门；台账 #134 / #136 / #138。

## 〇、这对顶层问题有什么贡献（约束 6 三问）

① **在主线**：§6 把它写成 Tier 2「动手前必须先确认」的唯一一条。
② **贡献**：Tier 2 是产品能力（prompt 24→72 token）。本门保护的是**已交付的 +6.74 dB
   一致性收益**不被静默摧毁 —— 若某个未被钳的张量在 L=80 下超过 65504，
   它在设备上变 inf，那正是 #102/#107 的死法（**实测 38% inf/nan ⇒ 图毁**）。
③ **前置条件**：全程宿主，**零设备**。

## 一、被检验的对象是什么

部署配置（18.67 dB）在 ONNX 里插了 **18 个** `Clip(±65504)`：

| 段 | 被钳张量 | 形状 |
|---|---|---|
| part1a | `linear_7/10/18/41/49`、`mul_131` | `[1,4096,·]` / `[1,4128,·]` |
| part1a | **`linear_23`** | **`[1,32,3840]` ← 唯一 caption-only** |
| part1b | `linear_105/121/129/137/145/153`、`mul_481` | `[1,4128,·]` |
| part2a | `linear_7/15/23/39` | `[1,4128,3840]` |
| part2b | （无） | — |

选择规则（`insert_clip.py:80-89`，逐字）：**非 STATIC 且 bitwidth==16 的激活，
`|a|max > 65504/1.2 = 54586.7` ⇒ 入选**；`|a|max` **实测优先，无实测用标定**。

🔴 **该集合是在 seq 32 下挑的。** L=80 改变两件事：
① `[1,4128,·]` → `[1,4176,·]`（多 48 个 caption 行）；② caption 内容更长
⇒ 经交叉注意力**影响所有行，包括图像行**。②是主要风险，不是①。

## 二、现有余量有多薄（①实测，part1b；②标定，其余三段）

`part1b_amax.json`（n=552 配对样本，seq 32 实测）：

| | 值 |
|---|---|
| 未被钳张量里实测最高：`linear_113` | **47,720** ⇒ 离 65504 只差 **1.37×** |
| 次高 `mul_381` / `mul_331` | 34,340 / 34,296 ⇒ 差 1.91× |
| 被钳的 `mul_481` 实测 | **64,474** ⇒ 已在 65504 的 **98.4%** |
| 实测/标定 比值（n=552） | min 0.111 / 中位 0.977 / **max 2.227** |

⚠️ **part1a / part2a / part2b 没有 `_amax.json`** ⇒ 它们的钳位集合**全部由标定挑出**，
而 #110 已证标定不可预测（0.09×~1.90×）。**本门同时补上这三段的实测。**

⇒ ②**余量薄到 1.37×，不能靠"caption 只多 1.16% 行"这类体量论证豁免。**

## 三、判据的操作化 —— 先用已知样本验证（约束 8，**不得跳过**）

本项目 2026-08-15 一天内三次把判据操作化写错。本门的操作化先验证：

**G0-known（前置自检）**：用**现有的 seq 32 数据**重跑一遍选择规则，
断言复现出的集合与盘上 `<seg>_clipped.json` **逐元素相同**（四段，18 个张量）。

- **不通过** ⇒ 我对规则的复现是错的，**停止**，后面所有比较都无意义。
- 通过 ⇒ 规则复现正确，可用于 L=80。

## 四、实现路径（按序，不许跳步）

| 步 | 动作 | 产物 | 预计 |
|---|---|---|---|
| 0 | **G0-known** 自检 | 控制台 | 秒级 |
| 1 | 四段 base ONNX 手术 32→80（`dit_seq_surgery.py --variant=base`，已改为走 `canonical_sources`，#138） | `transformer_part{1a,1b,2a_fixed,2b_fixed}_L80.onnx` | 分钟 |
| 2 | 用**官方 PyTorch FP32 文本编码器**产出 L=80 的 caption / cap_pad_mask（`official_caption.py` 需加 L 参数） | `caption_L80.raw`、`cap_pad_mask_L80.raw` | ~10 分钟 |
| 3 | L=80 FP32 前向链，逐段测**全部候选**的 `|a|max` | `<seg>_L80_amax.json` | **约 55 分钟/段 × 4 ≈ 4.3 小时**（宿主，无人值守） |
| 4 | 把规则套到 L=80 实测上，得 S80，与 S32 比对 | 判决 | 秒级 |

🔴 **步 1 必须用 `base`（不带 Clip）**：`_clip` 版本已经把值钳在 65504
⇒ **测不出真实 `|a|max`**，会把溢出藏起来。正确顺序是 base 上测量 → 再插 Clip。

🔴 **步 3 用一个真实的 72-token prompt（Arm C）**，不是把短 prompt 补零到 80。
理由：Arm C 是新能力的**实际最坏情形**；#137③ 已否掉"pad 行污染量程"
⇒ 补零臂预期更温和。**只有 Arm C 判决为改变时，才补做 Arm P（补零臂）做归因。**

⚠️ 步 3 只跑**一个** prompt ⇒ **n=1**（约束 7 / #131）。因此本门的判决**只能是单向的**：
「S80 出现新成员」是**硬结论**（存在性证明）；
「S80 == S32」**只能说"在该 prompt 下未发现新成员"**，不得写成"集合已验证稳定"。

## 五、验收判据（**事前锁定**）

令 S32 = 盘上 18 个；S80 = 规则套 L=80 实测。

| 判定 | 条件 | 动作 |
|---|---|---|
| 🟢 **PASS** | `S80 ⊆ S32`（无新成员） | 沿用 S32，Tier 2 继续。离开的成员**保留钳位**（<65504 时 Clip 是恒等，无害），保配置连续性 |
| 🟡 **CHANGED** | `S80 \ S32 ≠ ∅`，但新成员的 `|a|max` **未超 65504** | 按规则加入新成员（1.2 余量本就是为此留的）。**不算失败**，但白名单变了 ⇒ **与 FP32 的一致性**必须重测 L3 |
| 🔴 **FAIL** | 存在张量 L=80 实测 `|a|max > 65504` 且不在 S32 | **S32 在 L=80 下不成立**。必须用 S80 重建，且**不得复用 18.67 dB 的既有结论** |

**附带产出（无额外成本）**：part1a/2a/2b 的首份 `|a|max` 实测 ⇒ 顺带检验它们
**在 seq 32 下**由标定挑出的集合是否本来就有漏网（若有，那是**现有部署配置的缺陷**，
与 Tier 2 无关，须单独登记）。

## 六、成功与失败的判断依据（约束 4）

- **方向错误**长什么样：L=80 下大量张量普遍上涨 ⇒ 说明扩 caption 会系统性抬高量程，
  Tier 2 与当前钳位配方**结构性冲突**，需重新设计（而不是补几个 Clip）。
- **执行方法错误**长什么样：G0-known 不过；或 L=80 前向报形状错；或 `|a|max`
  出现 inf/nan（说明 FP32 前向本身坏了，不是模型性质）。**两者不得混为一谈。**

### 8.1 我把一个混淆源写成了"附带产出"

§五 末尾写「附带产出（无额外成本）：part1a/2a/2b 的首份 `|a|max` 实测」。
**那不是附带产出，那是一个混淆源。** 正确的划界是：

| 段 | L=32 侧的数从哪来 | 与 L=80 实测对比是否单变量 |
|---|---|---|
| **part1b** | **实测**（`part1b_amax.json`，n=552） | ✅ **同口径，就 L 而言干净** |
| part1a / part2a / part2b | **标定**（量化 encoding 反推） | 🔴 **非单变量**：口径与长度同时变 |

#110 已实测标定/实测比值横跨 **0.09×~1.90×** ⇒ 后三段一旦出现"新成员"，
**无法区分是 L 变了还是尺子从标定换成了实测**。这是本项目栽过四次的同一类错
（#61/#72/#74/#95）。

### 8.2 它影响什么、不影响什么

- ❌ **不影响 §五 的判据与决策**：「L=80 该钳哪些」的答案就是 L=80 实测集合，
  与差异来自哪无关 ⇒ **判据不需要改，也不许改。**
- ✅ **影响结论的措辞**：**不得**写「序列长度抬高了量程」。
  只能写「L=80 实测值是 X」。
- 🟢 **反而抬高了一件事的重要性**：若 part1a/2a/2b 的新成员来自「标定换实测」，
  那说明**当前已交付的 L=32 配置本身就漏钳了溢出张量** —— 那是**已上线版本的缺陷**，
  与 Tier 2 无关，须单独登记并单独评估是否值得修。

### 8.3 已排入的最小补测（**不是 Arm P**）

`linear_23` 在 **L=32 下的实测 `|a|max`**（`maxfp16_stats.py part1a --only linear_23_fc`，
约 1.5 分钟，宿主）。把那次对比从「三重混淆」降到「同口径，长度+内容捆绑」。

🚫 **不做完整的 Arm P（短 prompt 补零到 80）**，理由是代价门：
Arm P 要再花约 4 小时，而它**只买一个因果结论，不改变任何决策**
（§8.2）。⇒ 正确的处理是**放弃那个结论**，不是买证据。

⏸ **补测排在主链之后**：现在跑主链的进程 RSS 约 9 GB、宿主可用降到 10.5 GB，
而 `maxfp16_stats.py` 在可用 <3 GB 时会自杀。**同时起第二个重进程可能把我自己的
4 小时任务打死**（约束 9 第 7 条：本项目已两次把机器压死）。
