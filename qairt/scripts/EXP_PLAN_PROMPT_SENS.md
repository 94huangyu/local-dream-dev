# EXP_PLAN_PROMPT_SENS —— 为什么手机上"主体也变了"，PC 上"只有背景变"

**定稿 2026-08-26。判据事前锁定。** 缘起：用户 2026-08-26 在 app 上实测——
同 prompt（`masterpiece, best quality, a cat sat on a mat,`）、同 seed（165248929），
per-row 版与 Clip+FP16 版生出的图**猫、垫子、背景全不一样**；
而我在 PC 流水线报告的是"主体一致、只有背景不同"。**同样的配置差异，两处表现不一致，必须查清。**

---

## 一、两个竞争假设

| | 假设 | 若成立意味着什么 |
|---|---|---|
| **H1** | **prompt 约束强度不同**。PC 用的 prompt 明确指定了「**橘色的猫**、**木头桌子**」；手机的 prompt 只说「一只猫」「一张垫子」，颜色/品种/样式全是自由度 ⇒ 轨迹一偏就换 | 规律要从「主体收敛、背景发散」改写为「**prompt 钉死的收敛，没钉死的都会变**」。且**弱 prompt 下用户几乎感知不到我们的一致性改进** |
| **H2** | **量化文本编码器**。app 用量化 TE，PC 流水线用 **FP32 TE**；量化 TE 的误差把 caption 推偏，导致主体也变 | 需要把量化 TE 的贡献补测进来；18.67 dB 这个 transformer-only 的数字**低估了 app 的真实偏差** |

---

## 二、一个实验就能区分（关键设计）

**PC 流水线用的是 FP32 文本编码器。** 因此：

> 在 PC 流水线里换用**手机那个弱 prompt**，跑 per-row 与 Clip+FP16 两个配置（同噪声）。
> **TE 在这个实验里是 FP32、两臂相同 ⇒ 它被排除在变量之外。**

- 主体**也变了** ⇒ **H1 成立**（与 TE 无关，就是 prompt 约束不足）
- 主体**仍一致** ⇒ **H1 被否**，差异来自 app 特有的东西 ⇒ 转查 H2（量化 TE）

## 三、判据（🔴 事前锁定，不得事后改）

对照两张图（per-row vs Clip+FP16，同噪声同弱 prompt），逐项**肉眼判定并写明**：

| 项 | H1 成立的表现 | H1 被否的表现 |
|---|---|---|
| 猫的**毛色/花纹** | 明显不同（如白橘 vs 虎斑） | 基本一致 |
| **垫子**的颜色/图案 | 明显不同 | 基本一致 |
| 背景 | 不同（两种情况下都会不同，**不作为判据**） | — |

🔴 **判定必须自己打开图看**（约束 1），不得只看数值。
同时报数值（两图之间的像素相对 L2）**作为辅助**，但**不作为主判据**——
#121 已实测这类标量在该区间会排错。

**对照组（已有，不必重跑）**：强 prompt 下的三张图
（`recheck_new_fp32ref.png` / `htp_inloop_transformer_perrow4seg.png` / `htp_inloop_transformer_clip.png`），
实测表现为「同一只橘猫、同一张圆木桌，只有背景变」。

## 四、成本

| 步 | 成本 | 设备 |
|---|---|---|
| 让 `PROMPT` 可由环境变量配置 | 分钟 | 否 |
| per-row 弱 prompt 跑一次 | 约 12 分钟 | **是** |
| Clip+FP16 弱 prompt 跑一次 | 约 12 分钟 | **是** |
| 看图判定 | 分钟 | 否 |

**合计约 25 分钟设备时间。** 不建图、不改产物。

⚠️ **不做**：本轮不生成弱 prompt 的 FP32 参考（那要宿主跑满 8 步，成本高）。
主判据是「两个配置之间主体是否一致」，**不需要参考图**。
若 H1 成立且需要量化"离参考多远"，再另行决定是否补 FP32 参考。

## 五、后续（依结果而定）

- **H1 成立** ⇒ 必须回答一个更重要的问题：**在用户实际使用的弱 prompt 下，我们的一致性改进能不能被感知？**
  若不能，"继续提一致性"的价值要重新评估（这直接关系到要不要继续这条线）。
- **H1 被否** ⇒ 补测量化 TE 的贡献：把 app 的量化 TE 产出的 caption 与 FP32 caption 对比，
  再把 18.67 dB 修正为"app 端到端"的口径。
