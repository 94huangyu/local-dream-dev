# EXP_PLAN_ASPECT —— #86：支持不同比例（非 1:1）

**定稿：2026-08-31，执行前。判据事前锁定，不得事后修改（约束 4）。**
**用户需求**：明确点名「不同比例」，不是放大尺寸（放大已有内置升采样器，见 #86）。

---

## 〇、目标与非目标

**目标**：让 app 能出 4:3 / 3:4 / 16:9 / 9:16 的图，**速度与内存不退化**。

**非目标**：
- ❌ 不追求更大尺寸（1024² 以上）——扩散侧代价 O(N²)，且 app 已内置 RealESRGAN x4
- ❌ 不追求「任意尺寸」——HTP 的 context 是**为固定形状编译**的，做不到
- ❌ 不动量化配置、不动精度（双向约束：既不拿速度换精度，也不拿精度换速度）

---

## 一、为什么这条可做（本轮已勘察，非推测）

### 1.1 等 token 预算下，比例是**运行时免费**的

图像 token = `H×W/256`（除 8 是 VAE，除 2 是 patch）。①与契约自洽：
1024² → 128×128 latent → 64×64 = **4096**，而 unified 4176 − caption 80 = 4096 ✓

| 比例 | 尺寸 | latent | 图像 token | 相对 1024² |
|---|---|---|---|---|
| 1:1（现状） | 1024×1024 | 128×128 | 4096 | — |
| 4:3 | 1152×896 | 144×112 | **4032** | −1.6% |
| 3:4 | 896×1152 | 112×144 | **4032** | −1.6% |
| 16:9 | 1344×768 | 168×96 | **4032** | −1.6% |
| 9:16 | 768×1344 | 96×168 | **4032** | −1.6% |

⇒ ②**token 数几乎不变 ⇒ 速度、ION、PD 全部不变**（推算，待实测确认）。

### 1.2 transformer 侧：要改的「数据」只有一张表

①**实测**（`inspect_aspect_consts.py`）：
- `stack_1` int32 `[1,64,64,3]`，内容 `[33, h, w]`（通道 0 恒 33，通道 1/2 各 0..63）
  ⇒ **烘焙的二维位置网格**，按 `[1,H/2,W/2,3]` 重算即可，三行 numpy
- `unsqueeze_3 [4096,1]` 全 False｜`unified_mask [1,4128]` 全 True｜
  `val_572`/`val_566` 全 0 ⇒ **四者均为常量填充，只需改形状**
- RoPE 频率表 `mul_7/9/65/67` 均 `[512,24]`，覆盖 512 个位置而我们只需到 72
  ⇒ **不必重新生成**
- `val_70 = [16,1,1,64,2,64,2]` 是 patchify reshape（乘积 262144 = 16×128×128）
  ⇒ H/W **按位置区分**（第 3 位 / 第 5 位）

### 1.3 VAE 侧：只有 12 个形状常量，零索引表

①**实测**（`vae_survey.py`）：290 节点｜155 initializer｜444 value_info。
- 含空间维的小整数 initializer **只有 12 个**，全是 Reshape 目标：
  `[1,512,16384]` / `[1,512,128,128]` / `[1,512,256,256]` / `[1,512,512,512]` /
  `[1,256,1024,1024]` / `[1,128,1024,1024]` 等
- 🟢 **大整型 initializer 一个都没有** ⇒ **不像 transformer 那样有索引表要重算**
- 🟢 注意力权重是 `[512,512]`（通道维，与空间无关）；注意力序列长度 = 16384 = 128²
  ⇒ 等 token 预算下 N 不变 ⇒ **VAE 注意力代价不变**

## 二、🔴 最大的风险：数值歧义（VAE 比 transformer 严重）

Tier 2 改 caption 时验证过「32 无歧义」（头数是 30，不冲突）。**本次没有这个便利**：

| 数值 | 在 VAE 里同时是 | 出现在多少 value_info |
|---|---|---|
| 512 | **通道数** 与 **中间层空间边长** | 334 |
| 128 | **latent 边长** 与 **通道数**（`[1,128,1024,1024]`） | 212 |
| 256 | **通道数** 与 **中间层边长** | 160 |
| 1024 | 像素边长 | 96 |

🔴 **⇒ 严禁按数值匹配替换。** 必须按**张量秩 + 位置**：

```
4 维张量 [N, C, H, W]  => 只改第 2、3 位
3 维展平 [N, C, H*W]   => 只改第 2 位（且必须是 H*W 的乘积，要校验）
```

⚠️ **这条是本方案最容易写错的地方**，也是 Tier 2 §34.1/§34.2 两次事故的同一形态
（「只改 initializer 不够，value_info 也带旧长度」+「转换器不报错不等于图是对的」）。

## 四、判据（🔴 事前锁定）

### G1　形状自洽（宿主）
```
onnx.shape_inference.infer_shapes 无错误
且 图 IO 形状 == 目标（latent [1,16,144,112]，像素 [1,3,1152,896]）
且 patchify reshape 乘积 == 16 × H × W
不过 => 手术脚本有错，修完重来
```
⚠️ **通过不代表图是对的**（§34.2 实测：转换器不报错≠图正确）⇒ 必须继续到 G3/G4。

### G2　量程（宿主，#139 同款）
```
新 token 排布下，Clip+FP16 白名单的溢出集合 **0 新增** => 🟢 沿用现配置
有新增 => 🔴 停：这意味着改比例会改变激活量程，需重新标定 => 成本重估
```

### G3　装载 + 内存（设备 10 分钟）
```
五个 context 全部 createFromBinary 成功        => 🟢
ION 峰值 ≤ 现状 9100 MiB + 300 MiB            => 🟢（token 只少 1.6%，不该涨）
任一段报 0x3ea（PD）                          => 🔴 否决该比例
```

### G4　真机验收（设备 30 分钟）
```
① 出图：1152×896，**人工看图**，构图正常无伪影（约束 1：必须自己打开看）
② 速度：与 1024² 基线（160.87 s）相比 **|Δ| ≤ 5%**
   （token 少 1.6%，不该有明显差异；差异大 => 有东西没对）
③ 连续 3 张不被杀
④ 一致性：**不做跨比例 PSNR 比较** —— PSNR 跨不同图像不可比（#143）。
   本项目没有该比例的 FP32 参考，要有得先花 ~70 分钟/张生成
```

🔴 **G4④ 的划界**：本实验**不声称**新比例的一致性与 1:1 相同。
要声称就必须为该比例单独做 FP32 参考。**未做则如实写「未测」。**

## 五、失败归因（约束 4）

| 现象 | 是什么 | 下一步 |
|---|---|---|
| G1 不过 | 执行错（手术脚本） | 修脚本 |
| G2 有新增溢出 | **方向性成本变了**（不是错） | 重估：要重标定 ⇒ 成本翻倍，回来重新判值不值 |
| G3 报 PD | 受阻⛔ | 该比例否决；换更小 token 预算再试 |
| G4② 速度差异 >5% | 执行错或理解错 | 查是不是某段的 token 数算错了 |
| G4① 图坏 | ⚠️ **两种可能，必须分开**：① 手术错；② 模型没在该比例上训练过 | 先用**同一手术脚本做一个 1:1 的"空操作"版本**做对照——它必须与现状逐字节相同 |

🔴 **G4① 的对照是必须的**：没有它，「图坏」无法区分「我改错了」与「模型不支持非方形」。
