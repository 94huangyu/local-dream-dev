# EXP_PLAN_PARAMCAL —— `--param_quantizer_calibration mse/sqnr` 的代价门预筛

定稿时间：**2026-08-17 08:20**（**执行前定稿，判据不得事后修改**）
台账归属：新登记 **#66**（来自 `STATUS_FOR_REVIEW` 第九节候选 2）
性质：**约束 4·补 G0-cost 代价门**，全程宿主，**不占用设备**

---

## 0. 为什么现在做这个

1. **它与容量问题正交**：改的是权重校准方法，**不增加 encoding 数量、不撑大 context**
   （#57 的 PD 上限对它不构成约束）⇒ 无论四段在环落在哪个分支，它都还在队列里。
2. **它有很强的先验会失败，而先验不能代替实测**：
   `mse` / `sqnr` 校准对权重做的事是**砍掉量程换分辨率**，
   与 `percentile` 对激活做的是**同一个机制**——而后者已实测是净损害
   （主体余弦 0.7986 → 0.4793，代价 80 分钟 + 占用用户手机）。
   但约束 4·补 第 2 条写死：**机制从杠杆 A 迁移到杠杆 B，必须先验证迁移本身成立**，
   不得把激活上的证据直接当作权重上的"①实测支持证据"。⇒ **必须测，不得直接断言。**
3. 成本：**分钟级，零设备**。而它挡下的是 ~70 min 量化 + ~15 min 建图 + 设备时间。

## 1. 当前基线（本实验的对照面）

现行最好配置是 **per-row min-max**（#47，唯一有效手段）。
`perrow_feasibility.py` 已实测（121 个 part2 FC 权重张量）：
per-tensor 主体表示误差中位 **4.2002%** → per-row **1.1168%**（0.2781 倍）。

⇒ 本实验问的是：**在 per-row 已经拿到的基础上，换 mse/sqnr 校准还有没有额外空间？**
（不是问 mse vs per-tensor——那个比较没有决策意义，因为 per-row 已经在用了。）

## 2. 实现路径

对每个 FC 8-bit 权重张量、**逐行**（axis 与 per-row 生效的轴一致，
由 `perrow_feasibility.py` 已确认为轴 0）：

- **A 组（当前配置）**：`s = (max_row − min_row)/255`，`offset = round(min_row/s)`
- **B 组（mse 可达上界）**：在裁剪比例 `α ∈ [0.5, 1.0]` 上网格搜索
  （`lo = mn + (1−α)/2·(mx−mn)` 形式的对称收缩，以及单侧收缩），
  取**使 `‖W − Q(W)‖²` 最小**的那一组
- **B′ 组（sqnr 可达上界）**：同一网格，目标函数换成最大化 SQNR
  （对纯表示误差，SQNR 最大 ⇔ MSE 最小，故 B′ 与 B 数值等价，**只报一次并说明**）

⚠️ B 组是**可达上界**：SDK 的 mse 实现细节未知，真实收益 ≤ 本组。
⇒ **上界都没有收益 ⇒ 真实实现更不可能有** ⇒ 这是一个**单向否决**门，逻辑成立。
⇒ 反向不成立：上界有收益**不等于**SDK 实现能拿到，更不等于 HTP 上有收益（见第 4 节）。

口径：约束 7，同时报全量与主体（|w| ≤ p99）两个口径。

## 3. 判据（**事后不得修改**）

设 `E_A` = per-row min-max 的主体表示误差中位，`E_B` = mse 上界的主体表示误差中位。

| 分支 | 条件 | 判读与行动 |
|---|---|---|
| **P-否决** | `E_B ≥ 0.95·E_A` | mse/sqnr 在**可达上界**上都拿不到 5% 以上的改善 ⇒ **该候选出局，不许上机**，从队列删除并写明理由 |
| **P-无价值** | `0.80·E_A ≤ E_B < 0.95·E_A` | 改善 <20%。对照 per-row 自己是 **0.2781 倍**（改善 72%）⇒ 量级差一个数量级，**不值得 85 分钟**，降为最低优先级 |
| **P-值得** | `E_B < 0.80·E_A` | 有实质空间 ⇒ 可进入正式实验（届时另写方案，并**必须**先过 G0-cost 全量报数） |

**附带必报项（不作分支，但必须写进结论）**：
- 被裁剪掉的权重元素占比，以及它们占 `‖W‖²` 的比例
  —— 这正是 percentile 那次事后才补算、结果发现 0.026% 的元素占 98.75% 能量的那个量。
  **这次事前算。**
- 动态范围损失：`(裁剪后量程)/(原量程)` 的中位数。

## 4. 有效性边界（必须与结论一起写，防止过度声称）

🔴 **表示误差不是 HTP 误差的预测量**（#52 实测：同一改动 CPU 侧 Δcos −0.0014、
HTP 侧 −0.0526，差 37.6 倍；#53 据此推翻了 #9 的关闭论证）。

⇒ 本实验**只能否决，不能肯定**：
- `E_B ≥ E_A` ⇒ 没有任何机制能让它在 HTP 上变好 ⇒ **否决成立**
- `E_B < E_A` ⇒ **只说明表示层面有空间**，**不得**据此宣称 HTP 上会有收益

这条不是保守措辞，是本项目已经栽过的地方（#9 就是用表示误差/MSE 论证关闭的，后被推翻）。

## 5. 成功 / 失败判断

- **成功**：三组数字齐备，落入唯一分支。
- **失败·执行方法错误**：读不到权重 / 轴取错 ⇒ 修方法重跑，判据不变。
  轴的正确性以 `perrow_feasibility.py` 已验证的结果为准（轴 0），
  并在本脚本内**用 per-row min-max 复现该脚本的 1.1168% 中位数**作为操作化自检（约束 8）。
