# EXP_PLAN_P0B_FC_REPLAY —— Exact-real-FC standalone replay

定稿时间：**2026-08-21**（执行前定稿，**判据不得事后修改**）
归属：执行顺序 **P0-B**。前置门 #85 已过（per-axis encoding 可注入）。

---

## 一、它要回答的唯一问题

**#30 与 #39 直接矛盾，本实验是分离它们的唯一刀子。**

| 线索 | 实测 | 说的是 |
|---|---|---|
| **#30** 合成 MatMul 探针（K=64/1024/3840） | `E_htp/E_fxp` = 1.00 / 1.01 / 1.00 | **HTP 单算子是正确的**，无硬性精度地板 |
| **#39** 真实模型里的 `linear_99/100/102_fc`（同为 FC、同为 K=3840） | 正确定点 **0.012~0.19%**，HTP **2.72~2.87%**（差 20~230 倍） | **HTP 引入了超出正确定点的误差** |

同一种算子、同一个 K，一个说没问题一个说差两个数量级。
差异只可能来自 **①输入条件数**（真实激活是恶态的，#30 的探针是良态的）
或 **②图层面效应**（算子融合 #33 / VTCM 分块 #34）。**二者至今没被分离过。**

## 二、设计：把真实 FC 单独拎出来，在设备上重放

**关键是"精确"**：输入、权重、encoding 全部取自**真实那次运行**，**不重新校准**——
否则量化器会自己算出不同的 encoding，实验就不是"重放"了。
（#85 已证明 per-axis encoding 可经 `--quantization_overrides` 原样注入，这是本实验成立的前提。）

### 2.1 原料（多数已在盘上）

| 物件 | 来源 | 状态 |
|---|---|---|
| 真实输入 `x` | `p0_experiments/fc_inputs/cpu/out/Result_0/node_linear_99_pre_reshape.raw` | ✅ 已有 |
| 图内 HTP 输出（对照基准） | `p0_experiments/fc_probe/htp/linear_99_fc.raw` | ✅ 已有 |
| CPU 参考输出 | `p0_experiments/fc_probe/cpu/out/Result_0/linear_99_fc.raw` | ✅ 已有 |
| 权重 `W` + 其 **per-row encoding** | part1b 量化 DLC（`qairt-dlc-to-json` 读 `/graph/tensors/<名>/quant_params`） | 🔶 待抽 |
| 激活 encoding（`x` 与输出） | 同上 | 🔶 待抽 |
| 正确定点参考 | `scripts/fxp_sim.py`（P1~P4 前提门已过） | ✅ 已有 |

### 2.2 步骤

1. 从 part1b 量化 DLC 抽出 `linear_99_fc` 的权重张量名、`W` 数值、**per-row scale 数组与 axis**、
   以及输入/输出激活的 encoding
2. 建单算子 ONNX：`y = x @ W`，形状与真实一致（K=3840）
3. 写 overrides：`W` 用 per-axis（#85 臂 A 或 B 的格式），`x`/`y` 用 per-tensor，**全部照抄真实值**
4. `qairt-converter --quantization_overrides ... --float_bitwidth 32` → `qairt-quantizer`
   → `qnn-context-binary-generator --htp_socs sm8750`
5. 设备上喂**逐字节相同**的真实 `x`，取回 `y_standalone`

## 三、🔒 判据（事前锁定）

### V 门（先过，不过则作废）

| 门 | 要求 |
|---|---|
| **V1** | 注入后 DLC 里 `W` 的 encoding 与真实 DLC **逐个 scale 吻合**（相对差 <1e-6），且 `is_overridden=true`（#85 教训：不能靠 `Processed N`） |
| **V2** | 设备输出字节数正确（约束 3），`qnn-net-run` 打出 `Finished Executing Graphs` |
| **V3** | 喂进设备的 `x` 与图内那次**逐字节相同**（md5 比对） |

### 主判据

令 `E_standalone` = 单算子 HTP 输出 vs 正确定点（`fxp_sim.py`）的相对误差，
对照 `E_ingraph` = **2.72~2.87%**（#39 实测），`E_fxp_floor` = **0.012~0.19%**（正确定点自身）。

| 结果 | 判定 | 后续 |
|---|---|---|
| `E_standalone ≥ 0.5 × E_ingraph`（即 ≥1.4%） | 🔴 **真实数据/encoding 就能触发** | 问题在**算子级**。#33/#34 降级；转查这类输入的什么性质触发了它（条件数/离群分布） |
| `E_standalone ≤ 2 × E_fxp_floor`（即 ≤0.4%） | 🔴 **只有完整图才触发** | 问题在**图层面**。⇒ **#33/#34（融合、VTCM 分块）升为首选**，且 #39 不能再被解读为"HTP 单算子有问题" |
| 中间（0.4% ~ 1.4%） | 🔶 **两者皆有** | 记录比例，两条线都要查 |

⚠️ **不得事后放宽**。两个阈值分别锚在 `E_ingraph` 的一半与 `E_fxp_floor` 的两倍，
中间留了一个明确的"未定"区间——**不许把落在未定区间的结果说成任一侧**。

## 四、失败归因

- V1 不过 ⇒ encoding 注入没生效（#45/#85 的坑），修注入，不算方向失败
- V2/V3 不过 ⇒ 宿主接口或输入不一致（约束 3），修装置
- 三门全过 ⇒ **无论落在哪个区间都是有效结论**，本实验没有"失败"的方向，只有两个出口

## 五、成本

宿主抽取+建图+量化+建 context 约 1~2 h（单算子，模型极小）；设备 <1 min；分析 ~30 min。

## 七、🔒 P0-B2：**offset 项是不是那个触发因素？**（事前锁定）

### 七·1 依据

判据把方向指向"真实数据/encoding 的什么性质触发了它"。
最强的现成假设是 **#29/#40：非对称权重的定点展开 `y = Σq_x·q_w − z_w·Σq_x` 里，
offset 项与主项几乎等大（#40 实测 0.891~0.979），两个大数相减吃掉有效位。**

基线权重 offset = **−126**（非对称）⇒ offset 项存在。
对称权重 offset = **0** ⇒ **offset 项整体消失**。

### 七·2 单变量性（已用输出域 G0-cost 验证）

| 臂 | 正确定点 vs FP32（输出域） |
|---|---|
| A 非对称 per-tensor（基线） | 1.3323% |
| **B 对称 per-tensor** | **1.3550%（+0.0227 pp）** |

⇒ **表示代价几乎不变 ⇒ 唯一实质变量就是 offset。** 激活 encoding 保持不变。

⚠️ **注意先前的反向证据**：#7 在**完整图端到端**测对称权重，结果**更差**（余弦 0.6033→0.5507）。
本实验测的是**算子级 HTP 超出正确定点的部分**，与 #7 不是同一个量，**结论不得互相外推**。

### 七·3 判据（不得事后修改）

令 `E_A = 1.5544%`（已实测），`E_B` = 对称臂的 HTP 超出正确定点误差。

| 结果 | 判定 | 后续 |
|---|---|---|
| **E_B ≤ 0.5 × E_A（≤0.777%）** | 🔴 **offset 项是主要触发因素** | #29/#40 获强支持；转做"如何在不损失表示精度的前提下消除 offset 项" |
| **E_B ≥ 0.9 × E_A（≥1.399%）** | ✅ **offset 项不是触发因素** | #29/#40 **在算子级被证否**；转查其它性质（激活条件数 / 离群分布） |
| 中间 | 🔶 **部分贡献** | 记录比例，两条线都留 |

### 七·4 V 门

- V1：注入后 DLC 里 `val_1800` 必须是 **symmetric、offset 0**，且 scale 与注入值吻合
- V2：设备输出字节数 = 63,406,080（约束 3）
- V3：输入与 P0-B 那次**同一份文件**（md5 `eb9b583a0b41f8f37bfb69cc8077a9b5`）
- V4：**激活 encoding 必须与基线逐位相同**（单变量的前提）

## 八、【2026-08-22】P0-B2 结果 + P0-B3（🔒 事前锁定）

### 八·1 P0-B2 结果

| 臂 | 权重 encoding | 输出域表示代价 | **HTP 超出正确定点** |
|---|---|---|---|
| A 基线 | 非对称 per-tensor，offset −126 | 1.3323% | **1.5544%** |
| **B** | **对称 per-tensor，offset 0** | 1.3550%（+0.0227 pp） | **0.8310%（−46.5%）** |

⇒ ②**offset 项占算子级 HTP 超出误差的约一半**，#29/#40 获实质支持。
⇒ ②但**不是全部**：对称之后仍有 0.8310%。
（判据判定落在「部分贡献」区间，距「主要因素」线 0.777% 仅差 7%。）

### 八·2 与 #7 的矛盾已解开（不是矛盾）

#7 端到端测对称权重 ⇒ **更差**（余弦 0.6033→0.5507）。#7 自己的划界写明：
*"对称化同时粗化了 scale（中位 1.073×），两者无法分离"*。

**本实验把它们分离了**：因为量的是"HTP 超出**各自**正确定点"，表示变化被约掉。
合起来的机制：

- 对称化 **消除 offset 项** ⇒ 算子级 −47%
- 对称化 **同时粗化 scale 1.073×**，而 **#52 实测 HTP 对 scale 粗化的敏感度 = CPU 的 37.6 倍**
- ⇒ 端到端两者相抵，**净负** ⇒ 这就是 #7 看到的现象

⇒ ②**正确方向是「消除 offset 项而不粗化 scale」= per-row（对称 + 更细）。**

### 八·3 🔒 P0-B3：可证伪的预测

per-row 表示代价 **0.5050%**（比基线 1.3323% 还好）且 offset = 0
⇒ **预测：per-row 的算子级 HTP 超出误差应低于臂 B 的 0.8310%。**

令 `E_B = 0.8310%`，`E_C` = per-row 臂：

| 结果 | 判定 |
|---|---|
| **E_C ≤ 0.6×E_B（≤0.499%）** | 🔴 **细化 scale 在消除 offset 之上仍有实质收益** ⇒ 两机制叠加，**从机制上解释了 #47 为何是唯一有效手段** |
| **E_C ≥ 0.9×E_B（≥0.748%）** | ✅ **细化 scale 无额外收益** ⇒ per-row 的收益主要来自对称化本身 |
| 中间 | 🔶 部分叠加 |

⚠️ **划界**：per-row 臂的激活 encoding 取自 per-row DLC（与基线略有不同：
输入 scale 0.001154021244 vs 0.001149723656）⇒ **不是完美单变量**，
判读时须注明该项差异（0.37%，量级远小于观察到的效应）。
