# EXP_PLAN_VAE_DEVFIX —— #81 设备门：一行喂法修改在【量化 QNN VAE】上是否恢复画质？

定稿时间：**2026-08-21**（执行前定稿，**判据不得事后修改**）
前置：#80 已实测确认根因（宿主 fp32 上：现行 23.51 dB → 正确 **79.92 dB**）

---

## 一、为什么必须先做这一步（不能直接改 app）

约束 11 第 1 条：**先证明现状可用，再改一个变量。**
宿主 fp32 上的修复已证明；但设备上跑的是**量化 QNN VAE**，
它还叠了第二重损害（输入超校准量程 2.77 倍被钳，见 §15.22.3）。
**"修好喂法后设备上还剩多少损害"是 APK 交付的前置事实**，不测就交付等于盲改。

## 二、单变量设计

同一台设备、同一份 `vae.bin`、同一份 latents（`lat_8.raw`），**唯一变量 = 喂法**：

| 臂 | 输入 |
|---|---|
| **CURRENT** | `lat/0.3611 + 0.1159`（app 与全部宿主脚本的现行做法） |
| **FIXED** | `lat + 0.1159×0.3611`（#80 推定正确） |

参照系：官方 PyTorch VAE 输出（`scratch_runs/vae_gain_pxA.npy`，已落盘）。

## 三、🔒 判据（事前锁定）

### V 门（先过，不过则作废）

| 门 | 要求 | 抓什么 |
|---|---|---|
| **V1** | 设备在线；`qnn-net-run` 输出含 `Finished Executing Graphs` | USB 掉线伪装成执行失败（#65） |
| **V2** | 输出 `pixels.raw` 字节数 = **12582912** | 静默缩批（约束 3） |
| **V3** | **CURRENT 臂**对官方：高频能量 **4.021 ± 5%**、像素差 **13.28 ± 0.5** | 与 §15.21.7 是否同一配置。不过 ⇒ 不得与那次比较 |

### 主判据

改善率 `R = 1 − d_FIXED / d_CURRENT`（`d` = 对官方的平均 \|像素差\|）

| 结果 | 判定 | 后续 |
|---|---|---|
| **R ≥ 0.70** | **修复在设备上有效** | 进入 APK 交付（约束 11 四条铁律） |
| **R ≤ 0.30** | **设备上基本无效** | 设备侧损害另有来源，**不得交付**，回查 |
| 其余 | **部分有效** | 交付仍做，但需登记剩余损害并另开线索 |

### 附带记录（非判据）

- 两臂各自的高频能量与官方之比
- **FIXED 臂的残余差异 = 纯量化损害**
  （因为 fp32 + 正确喂法对官方已是 0.001 / 79.92 dB ⇒ 残余不可能来自导出或喂法）

## 四、失败归因

- V1 不过 ⇒ 设备/USB 问题，非模型问题（**报错说谎**，见约束 11·再补）
- V2 不过 ⇒ 宿主接口写错，重写输入
- V3 不过 ⇒ 当前 `vae.bin` 或 latents 与 §15.21.7 那次不同 ⇒ 只能自比，不得跨实验比较
- 三门全过而 R ≤ 0.30 ⇒ **方向错误**：设备侧损害主因不是喂法，如实记录并回查
