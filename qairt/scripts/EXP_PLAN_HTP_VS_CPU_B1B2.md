# EXP_PLAN_HTP_VS_CPU_B1B2 —— 把 HTP vs CPU 比对推进到 part1b / part2

定稿时间：2026-08-15（执行前定稿，判据不得事后修改）
前置：`EXP_PLAN_HTP_VS_CPU.md`（part1a 已完成，落在 1%~15.988% 中间带）
主线归属：A → 假设 C

## 0. 本轮必须先处理的方法论坑（part1a 没有）

part1a 的输入**全部由宿主给定**，所以两侧输入能做到逐字节相同。
**part1b / part2 的输入是上游图的输出，而上游两侧已经不同了**（`add_138` 差 2.35%）。
若直接把 HTP 的 part1a 输出喂进 HTP 的 part1b，再与 CPU 侧比，
测到的是「本段差异 + 上游带进来的差异」的混合物，**无法归因**。

因此必须拆成两个目的不同的实验，**不能只做一个**：

| | 输入来源 | 回答的问题 |
|---|---|---|
| **实验 A（逐段隔离）** | 两侧都喂 **CPU 参考**的上游输出（testB 现成文件） | 这一段**自身**的 HTP vs CPU 差异有多大 |
| **实验 B（级联）** | HTP 侧全程用 HTP 自己的上游输出 | 设备上**真实累积**的总差异有多大 |

A 用于归因（哪一段是差异源），B 用于判定量级（够不够解释色块）。

## 1. 预期结果（假设）

- **H-A**：某一段（很可能是含 15 个注意力块的 part2）自身差异显著大于其他段。
- **H-B**：级联到最后的噪声预测 `latents`，其相对 L2 **超过 15.988%**
  ⇒ 假设 C 足以成为根因候选。

零假设：H-B 不成立（< 15.988%）⇒ **假设 C 不足以解释"橙色色块"**
⇒ 假设树全部节点被排除，必须回顶层重提假设。这同样是重要结论。

## 2. 实现路径

设备 `/data/local/tmp/htpcmp` 已有 `qnn-net-run` + 全套 HTP V79 库 + `part1a.bin`。
再推 `part1b.bin`(1.47 GB)、`part2.bin`(2.93 GB)。
**推送前先比对主机副本与设备 app 副本的 md5**（同 part1a 的做法，防止跑错模型）。

- 实验 A：
  - part1b：喂 `testB/s0_transformer_part1b/*.raw`（= CPU 侧 part1a 输出），比 `unified`
  - part2 ：喂 `testB/s0_transformer_part2/*.raw`（= CPU 侧 part1a/1b 输出），比 `latents`
- 实验 B：
  - part1a(HTP 输出，已有) → part1b(HTP) → part2(HTP)，比最终 `latents`
  - 路由：part2 的 `adaln_input`/`unified_freqs`/`unified_mask` 取自 part1a 的 HTP 输出，
    `unified` 取自 part1b 的 HTP 输出。

全程 qnn-net-run **非 native 模式**（float32 进、float32 出），与 CPU 侧同口径。

## 3. 验收标准（判据，事后不得修改）

**判据 0（执行有效性）**：每次运行产出的每个张量，字节数必须与 CPU 参考侧对应文件**完全相同**。
任一不符 ⇒ 该次运行无效，结果不得解读。

**判据 A（归因）**：给出 part1a / part1b / part2 三段各自隔离条件下的相对 L2。
- 若某段显著大于其余段（≥ 3 倍）⇒ 认定该段为主要差异源。
- 若三段量级相当 ⇒ 差异是全局性的，不存在"某个坏算子"，记为均匀累积。

**判据 B（量级判定，本轮的核心）**：级联后最终 `latents` 的相对 L2：
- **< 15.988%** ⇒ **假设 C 不足以解释色块**。理由：Test B 实测在噪声预测相对 L2
  达 15.988% 时成图**仍然完好**。⇒ 必须回顶层重提假设，**不得**继续在 C 上深挖。
- **≥ 15.988%** ⇒ C 超出已标定的无害上界，成为根因**候选**。
  ⚠️ 但**仍不等于根因**：还须单独论证"这个量级能否造成橙色色块"。

> **必须预先声明的口径差异（防止事后自欺）**：
> 15.988% 这个标定点测的是「**量化 transformer** vs **FP32 transformer**」的噪声预测差异。
> 本实验测的是「**HTP 跑量化** vs **CPU 参考跑同一量化模型**」。
> 两者**不是同一个对照对**，设备的总误差 ≈ 量化误差 ⊕ HTP 误差，二者会**叠加**而非互斥。
> 所以：把本实验的数值与 15.988% 比，只能当**同量纲的数量级标尺**，
> **不能**说成"设备总误差 = 本实验数值"。若判据 B 落在临界附近（10%~20%），
> 必须补做「HTP 级联输出 vs FP32 参考」才能下结论，不得就地拍板。

**判据 C（离群形态）**：part1a 已发现差异呈**集中离群**（14~22 个点达 42σ）而非弥散。
本轮对最终 `latents` 同样要看分位数分布：
- 若最终 `latents` 也出现 >20σ 的离群点 ⇒ 记录其位置（图像 token 还是 caption token）。
- 弥散型误差与离群型误差对成图的影响机制不同，**必须分开报告**，不得只报一个相对 L2。

## 4. 成功 / 失败的判断依据

- **成功**：拿到 A、B 两组可复算数字，并按判据 B 给出明确分支结论。
- **失败·执行方法错误**：qnn-net-run 跑不起来 / 字节数不符 / 显存或存储不足。
  ⇒ 修方法重跑，判据不变，不构成对 H-B 的任何证据。
- **失败·方向错误**：级联最终 `latents` 与 CPU 侧逐位相同（相对 L2 = 0）。
  ⇒ 说明中间某步没真正用上 HTP 输出（路由写错），必须查路由，**不得**解读为"等价"。

## 5. 深度预算与放弃条件

- 预算：本轮一次跑完 A(2 段) + B(1 条链)，共 5 次 qnn-net-run。
- 放弃条件：若判据 B 判定"C 不足以解释色块"，**立即停止在 C 上的一切深挖**，
  回 `MAINLINE.md` 顶层重提假设。已深挖 3 层规则同样适用。

# 执行结果（2026-08-15，判据未做任何修改）

设备 PKX110 / SM8750。5 次 `qnn-net-run` 全部成功。
比对脚本 `scripts/compare_htp_b1b2.py`。产物 `D:\ZImage_Work\p0_experiments\htp_vs_cpu\`。
同源性：part1b/part2 的 `.bin` 与设备 app 副本 md5 逐一相同
（`83f16066e57a5ed6baa040b21b65b9e9` / `5994356c1691517a0230cfd97546edf0`）。

## 判据 0（执行有效性）：✅ 通过
所有输出字节数与 CPU 参考侧逐个相同（`unified` 63,406,080；`latents` 1,048,576）。

## 实测数据

| 用例 | 元素数 | 相对 L2 | 余弦 | 最大\|差\| | 最大/σ |
|---|---|---|---|---|---|
| A 隔离 part1a `add_138` | 15,851,520 | **2.35%** | 0.999729 | 144.8 | 42.1 |
| A 隔离 part1b `unified` | 15,851,520 | **19.47%** | 0.990125 | 2733.0 | 180.9 |
| A 隔离 part2 `latents` | 262,144 | **43.04%** | 0.905864 | 4.97 | 3.0 |
| B 级联 part1b `unified` | 15,851,520 | 19.04% | 0.990933 | 2633.9 | 174.3 |
| **B 级联 part2 `latents`** | 262,144 | **47.07%** | **0.898622** | 5.44 | 3.3 |

## 判据 A（归因）：✅ 存在主要差异源，且**差异是各段自生的，不是累积的**

隔离条件下 part1a **2.35%** → part1b **19.47%** → part2 **43.04%**，最大/最小 = **18.3 倍**。

**关键**：级联与隔离几乎相同（part1b 19.47%→19.04%；part2 43.04%→47.07%，放大仅 1.09 倍）。
⇒ ②严格推论：**上游误差几乎不放大，每一段的分歧主要在该段内部产生**。
   这排除了"某个上游坏张量污染全链"的模型，指向**HTP 执行本身在每段都持续偏离**。

## 判据 B（核心）：🔴 **47.07% ≫ 15.988%，H-B 成立**

级联后最终噪声预测 `latents` 与 CPU 参考差 **47.07%**（余弦 0.898622），
是"已实测证明成图仍完好"的标定点 15.988% 的 **约 3 倍**。

⇒ **假设 C 超出已标定的无害上界，正式成为根因【候选】。**

⚠️ 按第 3 节预先声明的口径纪律，仍**不得**就此宣布找到根因：
- 15.988% 测的是「量化 vs FP32」，本实验测的是「HTP 跑量化 vs CPU 跑同一量化模型」，
  **不是同一对照对**；设备总误差 ≈ 量化误差 ⊕ HTP 误差，二者叠加。
- 47% 不在方案规定的"临界带 10%~20%"内，故 vs FP32 的补充对照**不是**必需前置条件；
  但**"该量级能否造成橙色色块"仍未被证明**（差异 ≠ 根因）。

## 判据 C（离群形态）：最终 `latents` 是**弥散型**误差

```
p50=0.394(0.24σ)  p90=1.210(0.74σ)  p99=2.603(1.59σ)
p99.9=4.205(2.56σ)  p99.99=4.980(3.04σ)  max=5.443(3.32σ)
> 20σ 的元素数 = 0
```

与 part1a `add_138` 的 42σ 集中离群**形态不同**：到最终噪声预测这一层，
误差已经**弥散化**，没有极端离群点。⇒ 不能用"少数点炸掉"来解释，
它是**全局性的、每个元素都偏**的误差。

## 补充对照：HTP 逐位确定性（防"是不是随机噪声"）

同一输入把隔离 part2 重跑一次，两次输出 md5 **完全相同**
（`348f870855ec40bee73df469a1720744`）。
⇒ ①实测：HTP 执行**确定性**，上述 43~47% 是稳定可复现的系统性偏差，不是运行时噪声。

## 结论与下一步

**假设 C 第一次有了强证据**：HTP 执行 `.bin` 与 CPU 参考执行同一量化模型，
在噪声预测上系统性地差 47%，接近标定无害上界的 3 倍，且逐段自生、确定性、弥散型。

**但按项目纪律，"47% 的差异"仍不等于"它造成了橙色色块"。**
唯一能把这一步坐实的是**级别 2 验证**：让 HTP 的噪声预测进入完整去噪循环出图。
下一个方案：`EXP_PLAN_HTP_INLOOP.md`——即"在 HTP 上重做 Test B"。
Test B 用 CPU 参考跑同样的量化 transformer，出的是**清晰的猫**；
若换成 HTP 出的是**色块**，则在**同一实验框架内**完成闭环，C 被坐实为根因。
