# EXP_PLAN_ACTFP16 —— #102：对「病态激活张量」用 FP16（part1b 试点）

定稿时间：**2026-08-22**（执行前定稿，**判据不得事后修改**）
线索：**#102**（由 #53 代价门与 #48 阶段 1 共同导出）

---

## 一、依据（全部为实测/文档，非推测）

1. **FP16 主体表示误差恒定 ~0.021%**（其相对精度地板），而 uFxp_16 跨三个数量级：
   `unified` **4.4741%** / `add_153` **2.1123%** / `mul_333` 1.0363% / … / `mul_314` 0.0069%。
   机制：FP16 指数随元素走、**不共享 scale** ⇒ 治「离群值撑大量程」。
2. **两个口径同时改善**（`unified` 全量 0.1864%→0.0167%）⇒ **不是** percentile 那种以量程换分辨率。
3. **落地机制今天已实测可用**（#48 阶段 1）：`Float_16` 激活 + `sFxp_8` 权重，
   context 14.88 vs 15.10 MB ⇒ **权重字节不变**。
4. **硬约束（实测）**：part1b 的 655 个 16-bit 激活张量中，**6 个** `linear_{105,121,129,137,145,153}`
   的 `|a|max` 达 108k~238k，**超过 FP16 上限 65504** ⇒ 必须保持定点。其余 **98.2%** 安全。

## 二、为什么试点选 part1b（**并明写这是偏向便利的选择**）

§3.2 实测 **part2 才是支配项**。选 part1b 是因为：
① 它最小，量化/建图最快；② **#47 已给出同段可比基线**（E_all 19.24%→**7.87%**，主体余弦 0.7986）
⇒ 单变量对照的锚点现成；③ 本试点的首要目的是**可行性**（能不能建、PD 撞不撞红线、速度、会不会溢出），
可行性与选哪一段无关。

🔴 **但必须记录**：这仍然是「先修最方便测的」。**若可行性通过，下一步必须直接做 part2，不得在 part1b 上继续打磨。**

## 三、装置（单变量）

**唯一变量 = 激活数据类型**（uFxp_16 → Float_16，6 个溢出张量除外）。
权重保持**与部署完全相同**的 per-row 8-bit encoding（从现有 per-row DLC 抽出后注入）。

```
qairt-converter  --quantization_overrides <overrides.json> --float_bitwidth 16
   overrides 内容 = 全部权重 encoding（per-row，逐字取自现有 per-row DLC）
                  + 仅 6 个溢出张量的激活 encoding
   ⇒ 其余激活张量「缺 encoding」⇒ 落成 FP16（2.48 的机制，见指南 §二十七）
qairt-quantizer  --keep_weights_quantized --enable_float_fallback   # 🔴 不给 --input_list
qnn-context-binary-generator --htp_socs sm8750 --config_file <ext>  # 🔴 必带，devices soc_model 69 / dsp_arch v79
```

### 三·补 🔴 执行中发现：**这不是纯单变量**（2026-08-22，明写，不得事后粉饰）

G1 门读回产物发现，除激活外还有两类张量被连带浮点化：

| 张量 | 计划 | 实际 | 原因 |
|---|---|---|---|
| RmsNorm gamma（44 个） | 钉死 uFxp_8 | **Float_16** | 🔴 **后端强制**：HTP OpDef 里 **RmsNorm 没有「定点权重 + 浮点激活」的混合行**（指南 §二十七实查）⇒ 激活一旦 FP16，gamma 只能跟着 FP16。overrides 钉不住 |
| bias（51 个） | 不注入 | **Float_16** | 文档行为：`--keep_weights_quantized` 明写 *"Bias will be converted to floating point as per the output of the op"* |
| FC 权重（59 个） | 钉死 sFxp_8 per-row | **sFxp_8，409600 条 scale** ✅ | 按计划 |

⇒ **本实验的变量是「激活 + gamma + bias 三者一起 FP16」，不是「只有激活」。**
其中 gamma 那一项恰好覆盖了 #99（占端到端能量 0.70%）。
**结论措辞必须相应收敛：不得说「激活 FP16 带来了 X」，只能说「这一组改动带来了 X」。**
若结果为 🟢 且需要拆开归因，须另做单变量实验（RmsNorm 无混合行 ⇒ 可能拆不开）。

### 主判据（设备）

`E_all` = `unified` 相对 **FP32 参考**（`vs_fp32/unified_fp32.raw`）的**全量**相对 L2，
并同时报主体口径与前 1% 能量占比（约束 7；`unified` 集中度 99.83% ⇒ **以主体为准**）。

对照 = **#47 per-row 的同段基线**：`E_all 7.87%`，**主体余弦 0.7986**。

| 结果 | 判定 | 后续 |
|---|---|---|
| 主体余弦 **> 0.90** | 🟢 **显著改善** | **立刻推进 part2**（不得在 part1b 继续打磨） |
| 0.80 < 主体余弦 ≤ 0.90 | 🟡 有改善 | 评估是否值得四段全做 |
| 主体余弦 ≤ **0.7986** | ❌ **无改善或倒退** | 关闭 #102，记录理由 |

**并行硬约束**：`t_fp16 > 3 × t_perrow`（同段设备耗时）⇒ 🔴 标注产品级不可行（依据 #16）。

## 五、🔴 划界

- 表示误差的 214 倍**不是**收益承诺（#52：表示误差不是 HTP 误差的预测量）。**必要条件而已。**
- 本试点只做 **part1b**，结论**不得外推到 part2 / 端到端 / 成图质量**
  （#69/#70/#84：三把标量尺与成图质量反相关 ⇒ 最终仍须人工看图）。
- **BF16 未评估**：OpDef 里各算子都有 BF16 行，其指数范围同 FP32（可容 238k）但尾数仅 8 bit，
  可能是那 6 个溢出张量的替代方案。**本方案不做**，登记为后续。
