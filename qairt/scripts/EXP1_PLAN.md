# 实验 1 方案：单步端到端误差测量（执行前定稿，不得边做边改判据）

## 0. 为什么要做这个实验

13.9～13.17 全部在测**中间张量**的误差。但中间张量的误差大，不等于最终输出的误差大——
本会话已经实测到一个反例：`linear_38` 误差 168.87，经 RMSNorm + tanh 门控后到 `mul_127` 只剩 **0.18**
（衰减 930 倍）。所以"`add_138` 相对误差 26.9%"完全可能在下游被归一化吃掉。

**在回答"最终输出误差有多大"之前，任何修复投入都可能打空。**

## 1. 要检验的假设

**H1**：设备端画质"发闷"主要由 transformer 的量化误差造成。

**H0（对立假设）**：transformer 量化误差在传到最终噪声预测时已被大幅衰减，画质问题主因在别处
（VAE、text encoder、pipeline 代码、或采样调度）。

## 2. 实现目标

产出一个数字：**量化链路 vs FP32 链路，噪声预测（`part2` 输出的 `latents`）的相对误差**

```
rel_err = ||noise_quant − noise_fp32||₂ / ||noise_fp32||₂
```

以及配套的 max_abs_err、误差分位数、误差的空间分布。

## 3. 实现路径

两侧使用**完全相同的三段边界**（已核对：`zimage_fp32_pipeline.py` 加载的
`transformer_part1a/1b/2.onnx` 与部署的三个 `_quantized.dlc` 同源）。

**输入**：`calibration_raw\sample_0000` 的 `latents / timestep / caption / cap_pad_mask`
（正好是 `part1a` 的四个输入，无需额外构造）。

**FP32 侧**（onnxruntime）：
```
part1a → part1b → part2 → noise_fp32
```

**量化侧**（`snpe-net-run` 跑三个 `_quantized.dlc`）：
```
part1a(snpe) → 把输出写成 .raw → part1b(snpe) → 写 .raw → part2(snpe) → noise_quant
```

**段间接口**（来自 FP32 脚本，已核对）：
- `part1b` 输入：`adaln_input, add_131, add_138, select_45, select_46, tanh_19`（全部来自 part1a）
- `part2` 输入：`unified`（来自 part1b）+ `unified_mask, unified_freqs, adaln_input, latents_shape`（来自 part1a）

## 4. 执行前必须通过的有效性检查（防止方法错误伪装成结论）

这三条任一不通过，实验结果作废，先修方法：

| 检查 | 判据 | 目的 |
|---|---|---|
| **V1 dtype/shape 对齐** | 每个中间 `.raw` 的字节数 = shape 连乘 × dtype 字节数，逐个核对 | 防止 `unified_mask`(bool)、`latents_shape`(整型) 被当 float32 静默喂错 |
| **V2 量化侧 part1a 复现性** | 本次跑出的 `add_138` 误差 ≈ 321.8（8.4 节值），偏差 < 5% | 确认量化链路和历史测量一致，没跑错模型 |
| **V3 FP32 侧自洽** | 本次 FP32 的 `add_138` 与 `residual_chain_reference.npz` 中的值逐元素一致（相对误差 < 1e-5） | 确认 FP32 链路和历史参考同源 |

## 5. 预期结果（执行前登记，不得事后修改）

我的预测：**相对误差落在 5%～30% 区间**。

理由：`part1a` 输出 `add_138` 相对误差 26.9%，`part1b`/`part2` 还会继续注入；但下游存在多处
归一化，有实测证据表明归一化能把误差衰减 2～3 个数量级，所以最终值可能明显低于 26.9%。

**我明确承认另一种结果同样可能**：若 `part2` 末端由归一化主导，相对误差可能低到 1% 以下。
本实验对两种结果都是有信息量的，这是它值得做的原因。

## 6. 验收标准与判读规则（执行前定稿）

| 相对误差 | 判读 | 后续动作 |
|---|---|---|
| **< 1%** | H1 基本被否定 | 停止一切量化优化投入，转查 VAE / text encoder / pipeline 代码 / 调度器 |
| **1% ～ 5%** | 不确定 | 必须做实验 2（完整 8 步量化 transformer + FP32 VAE → 出图）才能定论 |
| **> 5%** | H1 未被否定，量化误差确实显著 | 做实验 2 确认视觉后果，再设计修复 |

**注意：本实验无论结果如何，都不足以单独确认 H1。** 它只能否定 H1（低误差）或"不否定"H1（高误差）。
确认 H1 必须靠实验 2 的图像证据。这一点必须写在结论里，不得含糊。

## 7. 失败分析预案（区分"方向错"和"执行错"）

| 现象 | 更可能是 | 排查动作 |
|---|---|---|
| 相对误差 > 100%，或出现 NaN/Inf | **执行错** | 段间 dtype/shape 喂错（V1 没做严）；检查 `unified_mask`/`latents_shape` |
| 相对误差极小（<0.01%） | **执行错** | 量化侧可能没真的用量化 DLC（跑成 fp32 dlc 了）；核对 V2 |
| V2 不通过（add_138 误差 ≠ 321.8） | **执行错** | 输入字节或模型选错 |
| V1~V3 全通过且误差 < 1% | **方向错** | H1 被否定，之前 13.9～13.17 的全部微观定位虽然正确，但与画质问题无因果关系 |
| V1~V3 全通过且误差 > 5% | 方向暂时保住 | 进入实验 2 |

## 8. 成本

- FP32 侧：3 次 onnxruntime 推理（part1a 已知约 150s，另两段更小）≈ 8～10 分钟
- 量化侧：3 次 `snpe-net-run`（每次约 4 分钟，模型加载占大头）≈ 12 分钟
- 合计约 22 分钟，单步。

**不在本实验范围**：8 步累积效应（单步误差是端到端效应的下界）。若单步已达判读阈值，
不必先跑 8 步；若单步在 1%～5% 灰区，再考虑实验 2。
