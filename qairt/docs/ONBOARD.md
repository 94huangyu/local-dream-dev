## 5. 五条最贵的教训（其余在 `CLAUDE.md`）

1. **共享权重省存储但涨常驻，方向相反**。5 图共享每图 +115 MiB 常驻，四段叠加 +375 MiB
   就把 app 撑死（实测 ION 9486 / MemAvail 208 被系统杀）。
   `ENABLE_GRAPHS` 只控制解开哪个图，**不控制共享块驻留多少**。
2. **判据一律写成与已知良品的差值，绝不用绝对阈值**；**缺对照臂就拒绝下判定**。
   用绝对阈值判过「新比例超量程」，补对照臂后发现现网同样超——那把尺子会把已知良品也判死。
3. **找峰值不许抽稀采样**。曾漏掉真峰值 9486 读成 7557，据此错误宣布「不是内存」。
4. **报错会说谎**：`adb push` 失败仍打印「1 file pushed」；`run-as sh -c 'cat > f'` 源不存在时
   照建 0 字节文件；后台任务的 exit code 会被链尾的诊断命令盖掉。
   ⇒ 以**字节数/产物**为准；**诊断命令不放链尾**。
5. **含反斜杠的字符串一律用 Edit/Write 工具，不走 heredoc**——转义展开一天触发 **9 次**，
   包括在写「修复转义」的代码时。每轮跑一次：
   `python scripts/check_stray_ctrl_bytes.py scripts docs local-dream/app/src/main`

## 6. 硬性纪律

- **宿主 23.7 GB 内存，单个建图进程占 10.6 GB ⇒ 不许并行跑重活**；
  启动任何计算前**实测**余量，不许推断（曾因「DLC 才 50 MB 应该很小」的推断把关键路径拖慢，实测 6.4 GB）。
